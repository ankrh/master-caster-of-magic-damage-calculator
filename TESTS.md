# Test list — Master/Caster of Magic damage calculator

`npm test` is the Node default and runs entries 1-3. `npm run test:ui` runs entries 4-11 through
Playwright against the no-cache dev server; `npm run test:all` runs both. Playwright is used only
for page behavior.

Select validation from what changed:

- Page code changes run `npm run test:all`.
- Other executable code, calculation data, or test changes run `npm test`.
- Documentation-only changes do not automatically run either suite. Check the affected text,
  links, references and task dependencies. If the edit changes an input interpreted by a checker,
  run that checker; run a broader suite only when the change can affect what it verifies.
- Read-only discussion or review does not require a suite run. Run a check when it is needed to
  investigate or substantiate a finding.

Any test file not named here is scaffolding and carries its own scheduled deletion.
`node tools/test_list_audit.js` checks that in both directions.

## 1. preset-checks

- Command: `node tools/preset_checks.js`
- Only it can fail: a wrong number anywhere in the 1,162-fixture corpus, headlessly. For each
  fixture it runs `presetToCardState` -> `cardStateToDerivationInput` -> `deriveUnitStats` ->
  `resolveCombat` and compares each side's total-damage mean and standard deviation, rounded as
  `renderDistPanel` publishes them, against the fixture's `expected` block at tolerance 0.002 —
  4,616 comparisons — plus the per-damage-category and healing moments where a fixture states them,
  23,240 comparisons over 163 fixtures. A fixture stating a mean without its spread halts; a corpus
  in which nothing is checked halts.
- **What the corpus cannot see.** It compares two moments, so: two distributions with the same first
  two moments are indistinguishable to it; a zero spread means determinism only to three decimals;
  and skew, multimodality and the joint across the two sides are invisible. A claim needing any of
  those is not a claim to bring here.
- A stated mean is authored; a stated spread is generated by `tools/generate_preset_stdev.js`. What
  the runner can fail on a spread is a change, never an infidelity.

## 2. node-unit-checks

- Command: `node tools/node_unit_checks.js`; `--only <suite>` runs one hosted suite alone.
- Only it can fail: `deriveUnitStats` and the engine/combat helpers in isolation, headless, in a
  `vm` context built from `index.html`'s script manifest — the claims about internal structure that
  no published number reaches. It evaluates no preset itself.
- **The families are named individually, one row per file.** An aggregate entry cannot see its own
  contents grow.

| Family file | What only it can fail |
|---|---|
| `ability_inputs` | which abilities reach `deriveUnitStats` at all |
| `ability_origins` | the origin table against the code it classifies |
| `backlog_checks` | the behaviour each settled backlog item fixed |
| `card_state_projection` | `cardStateToDerivationInput` in the headless core context |
| `derivation_stages` | the To-Block chance ledger, the figure sequence, the staged records |
| `derive_unit_stats` | per-ability, per-enchantment and per-version stat values, five engines |
| `hidden_control_gating` | INV-2's derivation half: a hidden control cannot move a number |
| `identity` | roster identities, ordered conversions, the live unit-type projection |
| `identity_record_choice` | which record each identity read takes |
| `phases` | each phase builder's distribution, and INV-1 on every one it publishes |
| `preset_applier` | `presetToCardState` over the corpus, control-free |
| `resolution_steps` | attack-specific sequences and the Weapon Immunity attack-to-weapon map |
| `step_traces` | step construction and the modifier trace the UI reads back |
| `version_gating` | `abilityVersionGated` as the one gating test, and `applyVersionGating` as the one implementation of the clearing |
| `version_scope` | the canonical engine-version scope table stays current |
| `warlord_abilities` | script-granted packages and the building grants only 1.5.12.9 makes |
| `damage_spell_f35_f37` | the Area iteration's HP cap; Magic Immunity before Black Sleep |
| `exorcise_f43` | CoM's common `0x0800` maps to the literal Exorcise consumer |
| `phase_order_f29` | modern opening-phase order, casualties recomputed between phases |

Four hosted suites have no file of their own — `source-order-f20` (every b/c/d step in source
order), `modern-gaze-riders-f25` (gaze types excluded from the touch-rider dispatcher),
`range-level-f33-f56` (modern hero ranged-distance exemption) and `defense-cap-bless-f32-f34` (the
to-block split after die 15 at an ordinary block probability, and Bless's realm gate). Each is a
function inside the family its subject belongs to, registered in `MIGRATED_SUITES` so its `--only`
anchor stays runnable.

## 3. citations

- Command: `npm run citations`
- Only it can fail: a citation that does not resolve. Every `PROVENANCE[id]` comment is VERIFIED or
  UNVERIFIED against its reviewed anchor with no stale manifest entry, and every citation into a
  shipped `.CAS` script resolves under `Reference docs/CAS citation grammar.md` — label and text
  anchors finding their landmark, and a line-list locator failing outright.

## 4. preset-equivalence-gate

- Command: `npx playwright test tests/preset-equivalence-gate.spec.js`
- Only it can fail: **the numbers the shipped page renders.** Everything after the derivation input
  is built — `readUnitStats`, `recalculate`, `resolveCombat`, `renderDistPanel` — is reached by no
  Node runner, and a defect there moves a number while every input field still matches. It applies
  and recalculates all 1,162 fixtures, reads the rendered moments off the `.avg` span, and compares
  them to the same `expected` blocks. It also compares the derivation inputs the page and Node build
  from each fixture, field by field, and carries the page's own preset harness over the derived
  control-path sample (`tools/preset_control_path_sample.js`, which derives the sample rather than
  listing it and halts if the vocabulary goes uncovered).
- What no suite can fail: a wrong rule inside `Calculator/card_state.js`, which both realms run and
  which moves both equally. The fixtures' authored means are the authority; no suite is.

## 5. invariants

- Command: `npx playwright test tests/invariants.spec.js`
- Only it can fail: INV-1 (the rendered distribution is a probability distribution), INV-3
  (`#swapBtn` is involutive and one swap exchanges sides), INV-5 (no console errors), INV-6
  (localStorage round-trip across a real reload, Reset yields a fresh page's state, and the
  share-link fixpoint). These are asserted once over the page, not restated inside each feature's
  suite; a feature that could break one in a way these cannot see is a gap to widen here.

## 6. version-gating

- Command: `npx playwright test tests/version-gating.spec.js`
- Only it can fail: INV-2. The set the UI hides per version equals the set the defs' gating
  disables, asked of `abilityVersionGated`; and a hidden ability cannot leak into the calculation on
  either input path — the card, which `applyVersionGating` clears, and the matrix, which reads
  persisted state a version switch only hides, so its reader carries the filter itself.

## 7. roster-smoke

- Command: `npx playwright test tests/roster-smoke.spec.js`
- Only it can fail: INV-4. Every unit of every version selects without a console error or a page
  crash, and the core stat fields become real numbers sourced from `units_*.js`.

## 8. modifier-traces

- Command: `npx playwright test tests/modifier-traces.spec.js`
- Only it can fail: the hover-chain contract. Source-ordered traces for every calculated stat,
  including the `a:baseCopy` boundary marker over the stat record and its To-Hit/To-Block
  projection; and their presentation in the tooltip and on the per-rider effective-resistance and
  effective-defense chains, each header naming the realm its roll asked.

## 9. rider-histograms

- Command: `npx playwright test tests/rider-histograms.spec.js`
- Only it can fail: the per-rider histogram contract — each contributing rider gets its own
  histogram in its phase's row, plotted in HP on one shared axis, with Cause Fear and Life Steal's
  healing the two deliberate exceptions; a rider gated off is omitted, one gated on but landing with
  probability zero is drawn with all mass at 0.

## 10. layout

- Command: `npx playwright test tests/layout.spec.js`
- Only it can fail: the page rendering usably — layout invariants, the mobile breakpoint, and touch
  tooltip behaviour. Nothing here asserts a number.

## 11. matrix

- Command: `npx playwright test tests/matrix.spec.js`
- Only it can fail: the matrix view's own surfaces — its drawers, and the property list it assembles
  itself from the version select. `matrixPropertyCandidates` is `data-scope="page"` and no Node
  context loads a page source, so the claim that the list follows the gate lives here while the gate
  itself is asserted in Node.
