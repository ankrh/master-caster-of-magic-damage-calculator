# F250.2 — remaining modern named bindings

Existing-source and raw-data reconciliation; no new executable instructions reconstructed.
The [combat inventory](F250.2.combat.evidence.md#dispatch-and-scoped-keys) remains the single
eleven-key claim table. This supplement separates its runtime-layout evidence from the still
unproved initialization route. It does not close F250.2 or change calculator behavior.

## What is already known

- [Typedec.pas](../Script%20source/CAS%20reference/Typedec.pas), `SpellTableT` at lines 449–474,
  declares `SpellGroup` and `EnchantmentID`. The former is at +0x2C and the latter at +0x90
  under the matching 184-byte record layout. The named `SpellGroup` accessor at 0x643530
  confirms the group read, stride and table pointer; see
  [F264.1's layout evidence](F264.1.evidence.md#spelltablet-layout).
- [SpellIDToUnitEnchantment](F250.2.combat.reconstruction.md), 0x5C2F24–0x5C2FA1,
  already reads +0x90 and accepts groups 1/13/14/15/16 from +0x2C. Zero maps to −1.
  The combat and [overland](F250.2.overland-store.evidence.md) stores, BaseUnits layer ownership,
  and recalculation aggregation are already established. None needs another derivation.
- [F250.1](F250.1.spell-classification.evidence.md) supplies the versioned INI records;
  [F250.4](F250.4.script-reconciliation.md) supplies the Rebuild/Conjuring Pact script mappings.
  These identify the configured meanings but do not themselves show initialization of the
  runtime table read by the compiled handlers.

Searches of the tracked reference/source tree and tools found no reconstructed spell-table
loader or Spells.dat conversion tool. Existing F264.1 explicitly leaves the key-to-offset
loading link open. This is a bounded search result, not proof that all loading code is missing.

## The shipped raw table narrows the question

`Raw install files/CoM2ModWarlord1.5.12.9/CoMWin1511/Spells.dat` has 73,784 bytes, exactly
401 records of 184 bytes. SHA256:
`3adf520c42c7d903ab77451392662ff484731efcf876eb169eb7172cac79bf1d`.
Reading a length-prefixed name at record+0 and signed little-endian dwords at +0x2C/+0x90 gives:

| Slot | Raw name | +0x2C | +0x90 |
|---|---|---:|---:|
| 53 | Vertigo | 13 | 25 |
| 67 | Mind Storm | 14 | 14 |
| 88 | Shatter | 16 | 11 |
| 89 | Warp Creature | 5 | −1 |
| 131 | True Sight | 1 | 41 |
| 162 | Weakness | 13 | 13 |
| 165 | Black Sleep | 13 | 46 |
| 272, 338, 343 | empty | 0 | 0 |

These are named raw records matching the base configuration, stronger than numeric coincidence
between unrelated INI fields. They are **not a runtime memory capture**. The same file cannot
establish Warlord's configured Shatter/Rebuild/Conjuring Pact records or its changed Weakness
group: those differ from these bytes. The unresolved question is which input populates the
runtime table, and when version-specific INI values replace or supply it.

Reproduce without disassembling code:

```python
from pathlib import Path
import hashlib, struct
p = Path('Raw install files/CoM2ModWarlord1.5.12.9/CoMWin1511/Spells.dat')
b = p.read_bytes()
print(len(b), hashlib.sha256(b).hexdigest())
for slot in (53, 67, 88, 89, 131, 162, 165, 272, 338, 343):
    o = slot * 184
    print(slot, b[o+1:o+1+b[o]],
          struct.unpack_from('<i', b, o+0x2C)[0],
          struct.unpack_from('<i', b, o+0x90)[0])
```

For locating the initialization route, the existing scanner's TD32 symbol query identifies
`@Init@LoadSpellsINI` at 0x62B6CC (length 0x3158) and `@Init@LoadSpellsINI2` at 0x62E824
(length 0x95C). These are **candidate metadata**, not reconstructed loading behavior or a sized
Method B packet. First locate the relevant callers/field writes and subtract existing coverage;
then count only the required missing slice. Reconstructing either entire routine by default
would repeat the overbroad-scoping mistake this task is correcting.

Reproduce the symbol metadata:

```powershell
python tools/scan_caster_binary.py syms "Raw install files/CoM2ModWarlord1.5.12.9/CoMWin1511/Caster.exe" LoadSpellsINI
```
