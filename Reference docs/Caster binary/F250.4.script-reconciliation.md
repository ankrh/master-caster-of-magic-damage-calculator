## API and hook interpretation

[Scripts.TXT](../Script%20source/CAS%20reference/Scripts.TXT), sections `Base unit vs Current Unit`,
`SETSTAT`, `SETENCHANTMENTFLAG`/`SETOLENCHANTMENTFLAG`/`SETCOMBATENCHANTMENTFLAG`, establishes:
selector `B=1` means base unit, `B=0` current unit; setter family separately selects the generic,
overland or combat enchantment layer. A combat-layer flag can therefore live on the base object.
Flag setters explicitly do not trigger recalculation. `FANTASTIC(U)` reads current identity;
`BASEFANTASTIC(U)` reads base identity. `HASCOMBATGLOBAL(W,CGE,1)` asks W's own combat global.

[MODDING.INI](../Script%20source/Warlord%201.5.12.9/MODDING.INI) binds `UnitRecalculateEarly=UnitCalcPre`
and `OverlandSpellEffect=OLSpell`. [Units.RecalculateUnits.pas](Units.RecalculateUnits.pas)
`$0059A002..$0059A02C` already maps the early hook, including its configured handle and calls,
before its main enchantment processing. These are existing script semantics plus existing
compiled hook mapping, not a missing interpreter reconstruction.
