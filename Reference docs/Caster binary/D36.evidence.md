# D36 — modern Raise Dead reconstruction evidence

## Scope, versions, and provenance

D36 reconstructs two complete half-open extents in the exact CoM2 1.05.11 `Caster.exe` whose
identity is owned by [README.md](./README.md): the Raise Dead gate/case
`$005CD1FF..$005CD372` inside `@Spells@InitializeCombatSpellcasting`, and the complete
`$0064435C..$00644377` `@Castercore@InitializeCombatSpellcasting` wrapper. Warlord 1.5.12.7
ships this same compiled engine. Evidence/build versions are therefore CoM2 1.05.11
`Caster.exe`, shared by Warlord 1.5.12.7, plus the executing Warlord scripts. Calculator versions
are `com2_1.05.11` and `com2_warlord_1.5.12.7`.

Before D36, [D32](./D32.evidence.md) owned the boundaries, caller/return context and fixed
reconstruction frontier, but no source-shaped body. D36 adds the complete assigned bodies to
[Spells.InitializeCombatSpellcasting.pas](./Spells.InitializeCombatSpellcasting.pas). This is an
evidence-only change: calculator output is unchanged, and the result supplies the modern Raise
Dead prerequisite for later R9-G1g work without implementing that item.

Method 4 was used. Two independent Codex GPT-5.6 Sol High derivations agreed on the semantic flow,
field layers, call/write order, arithmetic, wrapper ABI, and Warlord composition; their only
presentation difference was ledger granularity. The merged Codex derivation used the finer
boundaries and passed `tools/verify_derivation.py`. One Claude Opus 5 Medium review independently
rechecked the bytes, nesting, result flow, field layout and script boundary, found no semantic
error or surviving disagreement, and accepted both extents. Its one adopted precision advisory is
reflected here: D36 does not claim an exact ordering for the Warlord script-dispatch hook; the
script and compiled extent write disjoint state, so the compiled conclusion is order-independent.

## Reconstructed behavior

Both base and Warlord `MASTER.CAS` map `SRaiseDead=137` (`$89`) and
`SAnimateDead=195` (`$C3`). The assigned case begins:

```text
$005CD1FF  81 7D FC 89 00 00 00  cmp dword ptr [ebp-4],$89
$005CD206  0F 85 66 01 00 00     jne $005CD372
```

The false target `$005CD372` is the excluded Animate Dead sibling. On Raise Dead, the engine
reloads the target through pointer global `$0070802C`, performs a checked `1..40000` BaseUnits
lookup, and caches only that record pointer in TD32 local `[EBP-$28]`. It then performs the
following semantic operations in executable order:

1. Calls `@Units@RemoveAllEnchantments(target)` at `$005CD245`.
2. Clears base `Irrecoverabledamage`, `Undeaddamage`, `dead`, `undeaded`, `irrecoverable`,
   `confusioneffect`, `webleft`, and `Displayrace`, while setting base combat-layer
   `EncNoHeal=True`.
3. Restores base combat coordinates from the spell-target X/Y globals.
4. Copies calculated `Units[target].combatmaxmoves` to base `combatmovesleft`.
5. Calls `RecalculateUnits(True,-1,-1,-1)`.
6. Writes base `Totaldamage := (HpPerFigure(target) * base figures) div 2`, using checked signed
   multiplication, Delphi signed truncation toward zero, and checked `SmallInt` conversion.
7. Publishes the freshly reloaded target ID through pointer global `$00709BDC`, then calls
   `RecalculateUnits(True,-1,-1,-1)` again.

`Totaldamage` is damage sustained, not current health. Setting it to half maximum total HP revives
the unit at half health. The already checked consumer remains owned by
[Units.RecalculateUnits.pas](./Units.RecalculateUnits.pas) at `$005A0420..$005A04A9`: it consumes
combat `EncNoHeal` and derives race 21 plus `Fantastic=True`. D36 cites that consumer rather than
duplicating it.

The complete Castercore wrapper passes register argument `sp` through to the Spells function,
saves/reloads its Boolean `AL` result, and returns it unchanged. Its caller at `$00659F34` tests
`AL` at `$00659F39` and aborts the cast on false at `$00659F3B`. In the enclosing Spells routine,
the sole `Result=True` write is `$005CCA38`; no false write occurs at or after the Raise Dead case,
so an accepted Raise Dead path returns true.

## Enclosing context, excluded sibling, and Warlord composition

The enclosing TD32 symbol is `$005CC49C..$005CD644`; executable code ends with the ordinary
return `$005CD57F..$005CD586`. Inbound analysis finds only `$005CD09F` and `$005CD0BB` entering
the assigned start and none entering its interior. Ten earlier validation/case edges straddle the
assigned range to the ordinary return. Both Raise Dead gate paths converge at `$005CD372`, whose
bytes begin `81 7D FC C3 00 00 00`: the explicitly excluded Animate Dead case. The assigned case
contains no return.

Warlord's higher-precedence `COSpell.CAS` line 1328 checks both `SRaiseDead` and `SAnimateDead`.
For either, it scans living in-combat units and refreshes side-specific Goblin/Warboss, Mechanic,
and Hero master variables. It writes none of the target fields or globals above. The exact script
dispatch order is outside D36, but the disjoint write sets make the shared compiled producer
conclusion order-independent. The base CoM2 `COSpell.CAS` contains no corresponding revive block.

## Reproduction and completion gate

Run from the repository root with the README-owned executable path:

```powershell
python tools/annotate_caster_disasm.py $exe 0x5CD1FF 0x173 --inbound
python tools/annotate_caster_disasm.py $exe 0x64435C 0x1B --inbound
python tools/scan_caster_binary.py dis $exe 0x5CD1FF 0x173 InitializeCombatSpellcasting
python tools/scan_caster_binary.py dis $exe 0x64435C 0x1B InitializeCombatSpellcasting
python tools/verify_derivation.py $exe "Reference docs/Caster binary/D36.evidence.md"
```

The checker passes both ledgers separately: 17 and 5 contiguous rows, zero parent mismatches,
1/1 semantic conditional, 4/4 plus 1/1 semantic calls, and all mechanically recognized field
operations accounted.
