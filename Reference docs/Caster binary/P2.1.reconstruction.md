**Notation and continuation semantics**

- `M32[address]` and `M8[address]` are little-endian dword and byte memory accesses. `AL` is EAX’s low byte; an AL write preserves the upper 24 bits, and its source address is evaluated before replacement. Address arithmetic wraps to 32 bits. Signed comparisons interpret dwords as two’s-complement integers.
- `CMP32`, `TEST32`, `TEST8`, `ADD32`, `SUB32`, `IMUL32`, `NEG32`, `INC32`, `DEC32`, `SAR32`, `ADC32` and `XOR32` are notation for architectural operations, **not helper calls**. Arithmetic updates the named destination immediately and updates architectural flags according to that instruction. `CMP` and `TEST` update flags without storing a result; `INC` and `DEC` preserve CF. `MOV`, direct assignments, pushes and pops preserve flags.
- `ZF`, `CF`, `SF` and `OF` refer to the current architectural flags. `IMUL32 EAX,EAX,$17` stores the low 32 product bits in EAX and sets overflow before the following guard. `NEG32` and `SUB32` likewise write their real destinations before any handler call.
- `PUSH32 value`, `POP32 register` and `RET` represent the actual stack operations, including ESP changes. All right-hand operands and effective addresses are evaluated from the state at that operation.
- `call Name at address` includes the architectural return-address push and represents the actual executable call, with its entire incoming machine state. On a returning path, execution continues with its **actual returned registers, flags, memory and frame**. No call statement promises preservation, normalizes a byte result, restores a cached local, or recomputes an arithmetic result. Calls to reconstructed routines use the bodies below; other callees remain symbolic external boundaries.
- TD32 local names identify memory locations, not immutable Pascal variables. Every displayed `M32[EBP-offset]` uses the **then-current EBP**.
- `goto` marked “fall-through” explicitly identifies the continuation selected without an executable jump. Excluded sibling bodies are external code, not empty branches.

Every ledger is independent, has exclusive End addresses, and restarts at numeric N=0. `Within` identifies a row of that ledger using conditional jumps only. Compiler guards immediately followed by `BoundErr` or `IntOver` are excluded from nesting; unconditional jumps are not parents.
