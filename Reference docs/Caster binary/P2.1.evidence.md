## Animation and the existing effect chain

Both [versioned spell records](P2.holy-weapon-cast-boundary.md#versioned-binding-and-existing-admission-coverage)
name slot 124, group 15, realm 4 and enchantment 39. The new getters read realm at
spell-record +$34 and custom animation at +$78. The existing custom getter reads
byte +$76. Raw absence of an INI Custom key does not establish a zero runtime byte.
Keep the existing loader/cache conditions and each field's actual read time.

The [known combat prefix](F250.4.modern.reconstruction.md) reaches the generic animation
call at $65A002 under its live initializer/custom/group conditions. `SpellAnimationGeneric`
first selects a realm animation: realms 1..5 request 5,3,7,4,6 respectively; realm 0
or an unsigned value above 5 skips that request. Its subsequent custom test can
replace the selection with a nonnegative custom ID, or request 73 then reread and
negate the custom value before the pointer-based store at $659F22. The checked
negation writes EAX before any overflow handler; a returning handler's EAX is used.

The [existing setter](F250.4.modern.reconstruction.md#animation-state-setter) writes
the animation selector and clears the counter. It does not invoke the renderer.
The raw renderer table maps entry 4 to $678A31. On an invocation that selects it:

1. The counter's signed quotient by 4 is stored at EBP-$1C, then
   `checkspelleffectrequired` is called at $678A45 with the quotient in EAX.
2. The comparison rereads EBP-$1C after that opaque call. If the current signed value
   is below 12, the draw branch performs its bounds checks, separate live image reads
   and checked coordinate arithmetic. The selected image uses the current index;
   centering dimensions use element zero through two separate reads.
3. Otherwise $678B03 clears the current selector. After a nonzero `IsCombat` result,
   $678B12 reads the then-current spell and $678B17 calls the known wrapper $6456D8,
   which forwards EAX to the existing handler $5C9AAC.

The initial saved quotient is not immutable across the opaque call: subsequent local
reads use actual memory and the then-current EBP. Likewise handler-return registers
are not restored from cached arithmetic values. The source keeps the two raw setup
stack dwords; their interpretation as a Double 4.0 is not required.

At the known handler entry, the [existing group-1/15 writer](F250.2.combat.reconstruction.md)
converts the enchantment ID and writes the permanent object's combat source flag at
$5C9FD3. The [existing continuation](F250.2.truesight-continuation.reconstruction.md)
connects stable slot 124/group 15 to the common script call and then the full engine
combat recalculation. Reuse the [recalculation assessment](F250.2.recalculation-assessment.md)
for eligible-unit scope, persistent writes, copy/reset behavior, hooks and auras.
This does not prove equivalence to an unconditional current calculator pass.

`checkspelleffectrequired` remains opaque. Its TD32 extent is $6767A8..$6767F7;
canonical source search found no existing body. No statement here excludes an effect
or mutation inside it. Initializer internals, custom renderer alternatives, scheduling,
and overland UI entry also remain external. A model entered at the known effect handler
can retain those entry conditions without claiming one application across the entire
engine animation lifecycle. No whole-lifecycle reconstruction is required to close
these approved local extents.

## Scope, review and validation

The two seams comprise 118 target instructions and 155 animation instructions,
273 total, in 30 physical code extents, plus 28 table bytes. The raw-only initial
packet supplied another 749 already-covered context instructions: 1,022 total,
below the 1,200 cap. Raw metadata records binary/INI hashes, file offsets, extent
hashes, TD32 names, extraction commands and enclosing branch inventories. The installed
CoM2 and distributed Warlord executables were byte-compared and are identical.
The renderer's whole-routine linear inventory crosses table data; its selected code
extent and table edge were checked separately rather than trusting spurious decodes.

Full Method B used Astra medium and Claude Fable 5.1 medium. Initials and original-session
reciprocal reviews succeeded; fresh revisions received only own initial, received review,
raw evidence and applicable instructions. Both successful revisions were read before merge.
Immutable answers remain `.derivations/P2.1.{GPT,Claude}[.revised].md`; reviews and
session provenance remain under `.reviews/P2.1/` and `.reviews/P2.1.review-of-*.md`.

Review corrected ledger shape/nesting, repeated live reads, omitted arithmetic and
excessive timing claims. The coordinator also rejected the reciprocal review's assertion
that a handler preserves EAX. Both revised bodies preserve the architectural operation
before the handler and its returned state. The merge uses Astra's more explicit current-frame,
register and external-transfer notation; Claude's abbreviated saved-local prose and
excluded-body comment fall-throughs are not adopted. There is no surviving disagreement
about the supplied branches, reads, writes or destinations.

All 30 canonical ledgers pass `verify_derivation.py`: no gaps, declared parent mismatches
or unaccounted semantic elements. Byte/count/hash/table/inbound-join checks and source

before closure. Runtime suites add no coverage for this reference-only change.
