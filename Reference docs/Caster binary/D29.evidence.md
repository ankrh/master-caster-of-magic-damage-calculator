# D29 — `@Units@ApplyMagicWeapons` locate-and-bound evidence

## Scope and outcome

D29 located and bounded the shared CoM2 1.05.11 / Warlord 1.5.12.7 routine only; it did not
reconstruct its semantic body. The executable identity is owned by [`README.md`](./README.md).
The checked-in Warlord distribution contains a byte-identical copy at
`Raw install files/CoM2ModWarlord1.5.12.7/CoMWin1511/Caster.exe`, while its `WARLORD` tree contains
no engine executable or library.

| Virtual extent | `$00598D88..$005992CC` |

## Edge inventory

An exhaustive TD32-procedure decode and an independent executable-section relative-transfer scan
find exactly two direct callers, both targeting the entry, and no incoming edge to the interior:

| Call site | Bytes | Containing routine |
|---|---|---|
| `$0059E4B0` | `E8 D3 A8 FF FF` | `@Units@RecalculateUnits` |
| `$00649299` | `E8 EA FA F4 FF` | `@Castercore@CreateMercenaryPreview` |

At `$0059E4AD`, `mov eax,[ebp-$10]` establishes the unit-index EAX ABI for the first caller.
`CreateMercenaryPreview` is a declared CasApi entry point, but Warlord 1.5.12.7 scripts do not
reference it.

All 62 outgoing calls are classified:

| Target | Count | Disposition |
|---|---:|---|
| `$00406EE0 @System@@BoundErr` | 27 | compiler bounds guards |
| `$00406EE8 @System@@IntOver` | 34 | compiler overflow guards |
| `$005963F4 @Units@Ismagicalranged` | 1 | semantic dependency |

The semantic callee is already reconstructed in
[`Units.RecalculateUnits.R5.1c-a.evidence.md`](./Units.RecalculateUnits.R5.1c-a.evidence.md#005963f400596440).
The PE retains base relocations (`FileHeader.Characteristics = $818E`) and its populated `.reloc`
section includes a HIGHLOW entry for the `$0070A070` pointer slot. D33's review corrected the
earlier reloc-stripped premise and independently preserved the edge conclusion: an exhaustive
whole-file scan for stored dwords equal to any address in `$00598D88..$005992CC` finds 14 hits,
all in TD32 `.debug` line/address tables, and no stored code pointer. A deliberately computed
indirect call remains theoretically possible, but no direct or stored-address evidence indicates
one.

## Reconstruction frontier handed to D33

D29 handed exactly `$00598D88..$005992CC` to D33 for the base/current record fields, material
constants, gates and writes, while retaining `@Units@Ismagicalranged` as a cited dependency. D33
subsequently completed that body in [`D33.evidence.md`](./D33.evidence.md). Two compiler/data
details were already narrowed by this locate pass:

- `$00598E28 MOVZX` makes `$00598E2E JL` a dead Delphi `for`-loop guard. The byte at
  `[[$00709188]+$03]` is an inclusive upper bound, so the loop runs `N+1` times; `[ebp-$10]` is its
  unnamed compiler down-counter.
- `$0070A070` is initialized in `.data` at file offset `$00308270` to `$1A69F864`, which points
  into `.bss`. D33 identified the pointer and its runtime pointee producer.

The semantic frontier handed off was the record-layout binding, material constants and gates,
state-write meanings, runtime handling of `$0070A070`, and later Warlord script composition.
Neither caller, the RTL guards, the existing helper body, nor Warlord hooks belonged in D33's
reconstruction extent.

## Reproducibility and review

Applicable checks:

```powershell
python tools/annotate_caster_disasm.py $exe 0x598D88 0x544 --inbound
python tools/annotate_caster_disasm.py $exe 0x598D88 0x544 --raw ApplyMagicWeapons
```

They reproduce the enclosing TD32 extent, boundary bytes, complete decode, branch/call profile,
and inbound edges above. `verify_derivation.py` is intentionally not applicable because D29 is a
locate-only artifact with no source-shaped body or coverage ledger. Accordingly, all six
reconstruction completion counters are **not applicable** here rather than zero:

```text
unresolved ranges: not applicable
synthetic helpers without bodies: not applicable
semantic conditional jumps omitted: not applicable
semantic calls omitted: not applicable
state writes omitted: not applicable
declared parent mismatches: not applicable
```

Two independent Codex GPT-5.6 Sol High derivations agreed on the boundary, callers and exits. The
merged result then passed one Claude Opus 5 High byte-level review. Its five refinements—the dead
loop guard, pointer initializer, existing helper evidence, explicit not-applicable counters and
unnamed loop temporary—were verified against the executable and incorporated. No semantic
disagreement or boundary change survived review.
