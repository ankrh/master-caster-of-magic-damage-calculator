## Address result

Let `B=M32[0x709188]`, `u` be the checked unit index 1..40000 and `e` the checked enchantment index 1..100. The actual multiplication is checked `u*0x1E1`, then effective-address scaling by 4; the simplified stride is 0x784.

| Operation | Address evidence |
|---|---|
| Generic buff store | 0x5C9FD3: `M8[B + u*0x784 + 0x1AC1D68 + e] := 1` |
| Generic curse store | 0x5CA1F0: same expression |
| Combat getter | 0x6462D6: reads the same expression |
| Base getter | 0x646282: reads `B + u*0x784 + 0x1AC1CA0 + e`, 0xC8 bytes earlier |
| Warp store | 0x5C8EEF: pointer formed at 0x5C8E61 plus 0x5D0+e; 0x1AC1798+0x5D0=0x1AC1D68 |

WarpCreatureEffect maps opaque 0x40495C(EAX=3) return 0 to index 6 (`EncWarpAttack`), 1 to 7 (`EncWarpDefense`), otherwise 8 (`EncWarpResist`). It retries when that entry is already nonzero, sets a zero entry to 1, and exits without a direct store when its three initial tests are nonzero. No distribution or termination guarantee is inferred from TD32's `System.Random` name.

## Continuations and boundaries

- Initial nonzero guard and explicit rejection paths jump directly to cleanup 0x5CBC0E; they skip the supplied common tail.
- A signed nonpositive return from `ResistanceRoll` at 0x5CA0E5 jumps to0x5CBBCA without the subsequent curse store. The tail therefore also runs on this path; it is not success-only.
- Tail order: script bridge at 0x5CBBCD, then `RecalculateUnits` at 0x5CBBDC with AL=1, EDX=ECX=−1 and pushed −1, then conditional movement-helper calls. Called bodies remain opaque here.
- The bridge exports nine raw-named variables, including `SPELLTARGETUNIT`, and calls a runtime-selected script. The separate Mystic Surge call exports `TU`. Script filenames, imported-pointer initialization and actual script behavior are absent.
- True Sight/group1's post-store continuation is **open** at 0x5CA369. No shortcut from its store to the tail is inferred.
- Direct effect stores in CombatSpellEffect reload the imported target; WarpCreatureEffect uses its argument, supplied by the shown caller. Caller selection, target identity across opaque calls, guard lifecycle and persistence are not proved.

No direct write to the base-getter region occurs in these supplied instructions. This does not exclude writes in omitted code, other callers, overland code or scripts. All relevant cast provenance entries remain UNVERIFIED: modern combat-region evidence narrows their gaps but cannot validate the calculator's permanent backing choice, DOS behavior or full admission.
