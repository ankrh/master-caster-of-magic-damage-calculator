# F250.2 — overland generic enchantment store

The new fragment writes a byte to **`BaseUnits[u].OverlandEnchantmentFlags[e]`**. The direct
store is newly reconstructed; the containing object, flag layer and recalculation consumption
come from existing source. For both modern versions, the named True Sight route remains
conditional on the versioned INI fields reaching the runtime table and converter.

The local sequence checks the spell-slot value as unsigned 0..400, reads the runtime dword
at spell-table offset 0x2C, and accepts values 1 or 15. Other values exit to 0x5C503C.
It reloads the spell slot into EAX, calls the converter at 0x5C2F24, saves returned EAX,
and exits to 0x5C84B5 if that saved value is signed-negative. It then reads the target
indirectly through 0x70802C and the data-block pointer through 0x709188.

On paths bypassing the range-failure/overflow calls, the target `u` is 1..40000 and saved
index `e` is 1..100. Zero passes the earlier nonnegative test but reaches the final
range-failure call. At 0x5C4D79 the byte address is:

```text
(dataBlock + u*0x784 + 0x1AC1D04 + e) mod 2^32 := byte 1
```

The literal reconstruction preserves every conditional helper call. A returning helper may
change registers/memory; neither nonreturn nor preservation is assumed. The two signed IMUL
overflow checks remain, while pointer additions/scaled addresses have no explicit overflow
checks. The fragment falls through to 0x5C4D81, whose body is excluded.

## Existing source reused after derivation

[F264.1](F264.1.evidence.md#record-base-provenance) binds 0x1AC1798 to BaseUnits through the
named whole-record accessor. Its read table already identifies displacement 0x1AC1D04 plus
the enchantment index as `BaseUnits.OverlandEnchantmentFlags`. Subtraction gives 0x56C+e;
the declared one-based field starts at 0x56D in
[RecalculateUnits](Units.RecalculateUnits.pas). That declaration comes from the existing
layout evidence, not the new range checks. The existing copy/merges carry the base object's
overland flags into the calculated aggregate, as described in the
[combat reconciliation](F250.2.combat.evidence.md#record-ownership-and-recalculation-existing-source-reconciliation).

The [existing converter reconstruction](F250.2.combat.reconstruction.md) reads runtime
enchantment index dword+0x90 for the accepted groups and maps zero to −1. The new fragment
calls that same address. Both versioned True Sight [131] records provide group1/index41;
combining those sources supplies the named route conditional on runtime field loading and
entry into this fragment. We did not reconstruct the converter, getters or merge routines again.

The old 1010-instruction preflight included broader entry/tail work and known helpers. It is
not needed merely to establish this store. Any additional traversal must name the remaining
claim before expanding into those surrounding instructions.

## Limits and handoff

This result identifies the direct producer and its layer. It does not establish preceding
admission, pointer initialization, the enclosing cast lifecycle, later script/clear events or
final state. Rebuild's existing scripted producer is separately resolved in
[F250.4](F250.4.script-reconciliation.md). F250.2's remaining runtime-binding/admission claims
remain explicit; neither this fragment nor a known consumer verifies the calculator's
undifferentiated permanent True Sight step. No calculator number or provenance status changes.
