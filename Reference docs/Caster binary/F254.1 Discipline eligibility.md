# F254.1 — Discipline's hero and Fantastic exclusion, read for base CoM2 and for Warlord

Reading only, Method A. No `Calculator/` file was changed here; **F254.2 implements it.**
Everything below describes the two engines; §5 describes the calculator as F254.1 found it.

## 1. Outcome

**The exclusion is a spell-*targeting* rule, not an effect rule, and the two builds differ on the
hero half.**

| | base CoM2 1.05.11 | Warlord 1.5.12.9 |
|---|---|---|
| Hero excluded from the **cast** | **yes** (`NonHero=True`) | **no** — Warlord's Discipline rows carry no `NonHero` |
| Permanently-Fantastic excluded from the **cast** | yes (`SpellTypeGroup=15`) | yes (`SpellTypeGroup=15`) |
| Which record each term reads | `BaseUnits[]` — permanent, both terms | `BaseUnits[]` — permanent (Fantastic term only) |
| Non-cast routes to the flag | none | five; **none tests hero**, and only the every-turn Military Drilling pass tests Fantastic |
| The effect, once held | applied with no hero or Fantastic test | same (shared compiled code) |

So "does not affect heroes or fantastic units" is **wrong in both builds as written**, for
different reasons: in base CoM2 it describes a *targeting* refusal rather than an effect that fails
to apply, and it does not say *permanently* Fantastic; in Warlord the hero half is simply false.

## 2. The effect has no gate in either build

`Units.RecalculateUnits.pas:1541-1558` (`$0059EE76..$0059F198`, exact) is the whole Discipline stat
package: `+1` Defense, another at `level >= 2`, and at `level >= 3` the melee `+1` (gated on
`B.attack > 0`) and the non-magical-ranged `+1`. Two further blocks at `$0059F198` and `$0059F2A8`
add the level-4 movement and Negate First Strike off the overland and combat layers. **No block in
the three tests `ishero`, `Fantastic`, `race` or `unittype`.** This code is compiled and shared, so
it is the same in both builds; Warlord only remaps which enchantment id reaches it (§4).

A unit that holds the flag therefore gets the package, whatever it is. Anything F254.2 gates must
be gated where the flag is *granted*.

## 3. Base CoM2 — the cast is the only route, and it refuses both

### 3.1 The two spell-table flags

`[221] Discipline` in `Reference docs/Script source/CoM2 1.05.11 base/spells.ini` carries
`SpellTypeGroup=15`, `EnchantmentID=56`, `CastingLocation=0` and `NonHero=True` (lines 3662-3678).
`Reference docs/Script source/CoM2 1.05.11 base/MASTER.CAS~"SDiscipline = 221;"` and
`Reference docs/Script source/CoM2 1.05.11 base/MASTER.CAS~"EncDiscipline = 56;"` bind the two ids.
`NonHero=True` appears on exactly four base-CoM2 spells: Possession, Lycanthropy, Discipline,
Destiny.

### 3.2 Where those flags are read

Both are read by `@Spelltargeting@ValidUnitSpellTarget` (`$0053DB78`), reconstructed for F264.1 —
see `F264.1.evidence.md`, whose read table and `SpellTableT` layout this section reuses rather than
re-deriving.

- **The Fantastic term** is the group-15 arm at `$0053DC9A`: `if SpellTable[sp].SpellGroup =
  SGUnitBuffNormalUnit then if BaseUnits[u].Fantastic then Result := SPTMustBeNormal`. The read at
  `$0053DCC5` uses displacement `$01AC1867`, i.e. `BaseUnits` + 207 — the **permanent** record.
  This is the buff half of the F264.1 asymmetry: its group-16 curse mirror reads the calculated
  record from otherwise identical code. Discipline is group 15, so it takes the permanent read.
- **The hero term** is the table-driven arm at `$0053DF46`: `if SpellTable[sp].Nonhero then if
  BaseUnits[u].ishero then Result := SPTNoHeroes` (`$0053DF7B`, `-11`). The read at `$0053DF71`
  uses `$01AC187A` = `BaseUnits` + 226 = `ishero` — again the **permanent** record.
  `SpellTableT.Nonhero` is the byte at `+$5D`; `SPTNoHeroes = -11` is `SharedConstants.pas:511`.

### 3.3 The gate covers the overland cast as well as the combat one

`ValidUnitSpellTarget` has one definition and five call sites, established by scanning `.text` for
`E8` relative calls (`tools/scan_caster_binary.py`):

| Caller | Path |
|---|---|
| `@Spelltargeting@ValidCombatSpellTarget` `$0053C8A4` | combat |
| `@Aispelltargeting@AIOverlandBuffTargeting` `$0055DBDC` | overland, AI |
| `@Uispell@ValidSpellTargeting` `$006586F0` | overland |
| `@Ui@SpellTargetingUI` `$006D7951`, `$006D7AF6` | overland |

plus the pure thunk `@Castercore@ValidUnitSpellTarget` `$006437D0`, which does nothing but forward
to `$0053DB78`. `@Spelltargeting@IsOverlandUnitTargetingSpell` `$0053D820` admits
`SpellGroup` in {1, 15} (and ids 173, 93) to the overland unit-target path, so group 15 is an
overland unit-targeting class by construction. `CastingLocation=0` is shared by eleven other
base-CoM2 unit buffs (Iron Skin, Regeneration, Invisibility, Flame Blade, Immolation, Holy Weapon,
Heroism, Lionheart, Invulnerability, Cloak of Fear, Wraith Form), i.e. "castable in both places".

### 3.4 No other route exists in base CoM2

No shipped base-CoM2 `.CAS` writes `EncDiscipline`; `SDiscipline` occurs twice in the set, in
`Reference docs/Script source/CoM2 1.05.11 base/MASTER.CAS~"SDiscipline = 221;"` and in
`AISSpell.CAS`'s AI spell list. Base CoM2 has no Military Drilling, no Enlightenment, no Power of
Life and no Mystic Surge Discipline arm; `itempow.ini` grants no Discipline. So in base CoM2 the
**cast is the whole surface**, and the tooltip's two claims are true of it — subject to the two
corrections in §1.

## 4. Warlord — the hero exclusion is gone, and there are five non-cast routes

### 4.1 The ids move

`MASTER.CAS~"EncDiscipline = 87;"` is Warlord's live flag; the base flag 56 survives as
`MASTER.CAS~"EncDisciplineOld = 56;"`.
`UnitCalcPre.CAS!NOFIERYFURY!+11 "IF (GetEnchantmentFlag(U,EncDiscipline,0)>0) THEN {"`
copies the new flag into the old one on every recalculation, which is how the compiled §2 package
still fires. That copy reads selector 0 — the **calculated** aggregate — and tests neither hero nor
Fantastic.

Two spell rows exist. `[221]` is renamed `Tactical Drill` (`MASTER.CAS~"STacticalDrill = 221;"`),
keeps `SpellTypeGroup=15` and `EnchantmentID=56`, gains `Unobtainable=True` and
`InvalidTreasure=True`, and is granted to every wizard at
`EnterGame.CAS~"SETSPELLDATA(I,STacticalDrill,1);"` and again at
`OverlandEndTurn.CAS~"IF (SPELLSTATE(W,STacticalDrill)=0) THEN { SETSPELLDATA(W,STacticalDrill,1); }"`,
so it is castable. `[271] Discipline` (`MASTER.CAS~"SDisciplineWarlord = 271;"`) is
`SpellTypeGroup=15`, `EnchantmentID=87` and `Disabled=True`. The Centurion carries
`Spellability=271` with `Spellcharges=3` (`Unit rosters/Warlord mod unit data/UNITS.INI`, `[6]`) and
is itself a hero (`HeroType=7`). **That is a configuration fact, not a traversal:** whether a
`Spellability` charge is targeted through `ValidUnitSpellTarget` was not read (§7), so the charge is
evidence that Warlord means Discipline to be castable by a hero, and not evidence about which gate
its target passes.

**Neither row carries `NonHero`.** Warlord's four `NonHero=True` rows are Possession, Lycanthropy,
Apotheosis and Blaze of Glory. Both rows keep `SpellTypeGroup=15`, so the permanent-`Fantastic`
refusal of §3.2 still applies to both.

`OLSpell.CAS!NOPERMENCHANT!-5 "SETENCHANTMENTFLAG(TU,EncDiscipline,1,1);"` is the script's
interception of the Tactical Drill cast: it **sets** the permanent flag 87 and **clears** the
permanent record's overland layer of flag 56 —
`OLSpell.CAS!NOPERMENCHANT!-4 "SETOLENCHANTMENTFLAG(TU,EncDisciplineOld,1,0);"`, value `0`, so the
row's own `EnchantmentID=56` cannot also stand. It runs behind the Tattoo Magic research gate at
`OLSpell.CAS!NOPERMENCHANT!-74 "IF (SPELLSTATE(W,STattooMagic)<>2) THEN { GOTO"`; without that
research the compiled path applies the row's own `EnchantmentID` instead. Neither arm tests hero.

### 4.2 The five non-cast routes, and what each tests

| Route | Site | Hero test | Fantastic test |
|---|---|---|---|
| Military Drilling / Enlightenment, at unit creation | `CreateUnit.CAS!HASEVILPRESENCE!+51 "SETENCHANTMENTFLAG(U,EncDiscipline,ABase,1);"` | none | **none** |
| Military Drilling, the every-turn upgrade pass | `OverlandEndTurn.CAS!NOMAGITEKSCI!+8 "SETENCHANTMENTFLAG(U,EncDiscipline,1,1);"` | none | `OverlandEndTurn.CAS!NOMAGITEKSCI!+2 "IF (BASEFANTASTIC(U)>0) THEN { GOTO"` — permanent |
| Air Support Doctrine's summon (`MASTER.CAS~"STAirSupportDoctrine = 380;"`, Aerial Support Drones), after it clears the new unit's Fantastic | `COSpell.CAS~"SETENCHANTMENTFLAG(NEWU,EncDiscipline,1,1);"` and `OLSpell.CAS~"SETENCHANTMENTFLAG(NEWU,EncDiscipline,1,1);"` | none | not needed — the block above has already run `SETSTAT(NEWU,AFantastic,1,0)` |
| Power of Life | `COSpell.CAS!POWEROFCHAOS!+13 "SETCOMBATENCHANTMENTFLAG(TU,EncDiscipline,1,1);"` | none | **none** |
| Mystic Surge, arm `R=27` | `SpellMysticSurge.CAS~"IF (R=27) THEN { SETCOMBATENCHANTMENTFLAG(TU,EncDiscipline,ABase,1); }"` | none | **none** |

A sixth site copies the flag across a transformation rather than granting it:
`COSpell.CAS~"IF (GETENCHANTMENTFLAG(OU,EncDiscipline,1)>0) THEN { SETENCHANTMENTFLAG(NU,EncDiscipline,1,1); }"`.

Power of Life is `[367]` with `SpellTypeGroup=1` (`SGUnitBuff` — any own unit;
`SharedConstants.pas:542`) and `MASTER.CAS~"SPowerOfLife = 367;"`, so no normal-unit arm applies to
it and no arm in the extent F264.1 read refuses a hero or a Fantastic unit for a group-1 spell.
Mystic Surge is a random grant with no unit predicate.

**What the table establishes is that no grant block tests hero, not that every route can reach every
recipient.** Two of the five are structurally restricted — `CreateUnit.CAS` receives a
city-produced unit and the Air Support Doctrine block writes its own summoned `NEWU` — so they are
evidence about the *predicate*, not about hero recipients. The routes that do demonstrably reach a
hero or a permanently-Fantastic unit are **Power of Life and Mystic Surge**, both of which take an
arbitrary own unit as `TU`. That is enough for the conclusion this reading needs: **in Warlord a
hero, and a permanently-Fantastic unit, can hold Discipline.**

## 5. What this makes of the calculator today

- `c:discipline` (`stats.js`, `disciplineDefMod` / `disciplineAtkMod`) applies the package with no
  hero or Fantastic term. **Correct — §2 says the engine has none.** F254.2 must not gate here.
- `buffs:discipline:cast` (`permanentCastFlagSteps`, `stats_identity.js`) is `isCoM2`, i.e. both
  modern builds, and its `when` is the card's mark alone. **This is the gap.** It needs a
  permanent-`fantastic` term in both builds and a permanent-`ishero` term in **base CoM2 only**.
- `training:militaryDrilling` (`combat_abilities.js`) is `!!outlanderReform.militaryDrilling &&
  !u.fantastic`. **No hero term is warranted** — §4.2 shows neither Military Drilling site tests
  hero, and F254.2 should add none. Its Fantastic term is a **hybrid the tree already declares**,
  not a match: the gate comes from the every-turn pass, while the record it reads is the
  creation-time one (F245; `militaryDrillingReadsFantasticAtItsOwnRankWarlord`,
  `presets_curses_and_undead.js`). This reading finds that the creation entrance
  (`CreateUnit.CAS!HASEVILPRESENCE!+51 "SETENCHANTMENTFLAG(U,EncDiscipline,ABase,1);"`) has
  **no Fantastic test at all**, so a strictly
  creation-faithful step would grant to a permanently-Fantastic unit and the current step does not.
  That is a live discrepancy between the two entrances, already named as such by F245's ruling.
  **F254.1 does not reopen it and F254.2 should not either** — it is a separate decision, and this
  reading records it rather than settling it.
- Both tooltips (`enchantments.js`, keys `discipline` and `disciplineWarlord`) say "Does not affect
  heroes or fantastic units". §1 says why both are wrong.

### 5.1 Which record the new terms read

`ishero` is written by no step (`stats_identity.js`), so its position is immaterial.

`fantastic` is not, and the right read is **positional, not hoisted**. `ctx.base` is unavailable
here: it is published by `a:baseCopy` (`stats_sequence.js`), four phases *after* `buffs`, so F263's
`outlanderSapiensAt` is not the precedent — that gate stands behind the copy. The precedent that
fits is the `training` one: a gate ranking ahead of `a:baseCopy` reads the permanent flag as it
stands at its own rank, because "the permanent record a gate asks about is the one the phase is
building" (`stats.js`, `naturalSelectionEligibleAt`).

`buffs` *is* the permanent-record phase, so the running `u.fantastic` at `buffs:discipline:cast`
**is** `BaseUnits[u].Fantastic` as of that cast. `buffs:destiny` sets the flag and
`buffs:spiritLink:fantastic` clears it, and both are ordered *after* `buffs:discipline:cast` in both
modern manifests (`stats_manifests.js`). That ordering is the chain's declared cast order, and under
it the positional read is the correct one and its consequences are intended: a Discipline cast that
precedes Apotheosis lands, and one that followed it would be refused. It is a ruling, not a
coincidence — and F254.2 should read `u.fantastic` at the step, not reach for a base or template
snapshot.

### 5.2 Proposed tooltip wording

Base CoM2 `discipline`: replace `Does not affect heroes or fantastic units.` with
`Cannot be cast on a hero, or on a unit that is fantastic on its permanent record.`

Warlord `disciplineWarlord`: replace the same line with
`Cannot be cast on a unit that is fantastic on its permanent record. Heroes can receive it.`
The control's existing first line, `Arcane unit ability, also granted permanently by Military
Drilling.`, is accurate: the "arcane unit ability" is the Centurion's `Spellability=271` charge.

## 6. Expected movement, and a correction to the F254 item body

F244.3d measured a hero gate at **36 digest cases per version, 72 modern**. Under this reading the
hero gate belongs to base CoM2 alone, so F254.2 should expect roughly **36, not 72** from that half,
and **zero in Warlord**. A Warlord movement from the hero half would be a defect in the
implementation, not a finding.

No preset fixture pairs Discipline with a hero or with a Fantastic unit — the six Discipline
fixtures in `presets_immunities_and_abilities.js` are all normal CoM2 units — so the Fantastic case
has to be stated by a new fixture, as the item body already says.

## 7. Boundary of the claim

- §3.2 reuses F264.1's reconstruction of `ValidUnitSpellTarget` rather than re-deriving it. What is
  new here is only which arms Discipline takes, and that is settled by its `spells.ini` row.
- `ValidUnitSpellTarget` assigns `Result` through a ladder with **no early exits** and continues
  past `$0053E216`; a later arm can overwrite an earlier one. Neither `SPTMustBeNormal` nor
  `SPTNoHeroes` is overwritten by anything in the extent F264.1 covered, but the tail past
  `$0053E216` is unread. This bounds "the cast is refused", not "the flag is tested".
- Whether the unit-spell-charge cast (`Spellability`) reaches the same gate is inferred from
  `@Ui@SpellTargetingUI` being the human targeting entry point, not read from the charge path. So
  §5.2's Warlord wording is stated for the wizard's cast; if a charge bypasses the gate, the wording
  is still not *wrong*, but it is not exhaustive.
- §4.2 reads each grant block's **predicate**. It does not establish that every route can reach
  every recipient: `CreateUnit.CAS` is entered with a city-produced unit and the Air Support
  Doctrine block writes its own summon, so "no hero test" there is not "a hero gets it there". The
  hero and Fantastic conclusions for Warlord rest on Power of Life and Mystic Surge, which take an
  arbitrary own unit.
- The disagreement between Military Drilling's two entrances — creation with no Fantastic test,
  the every-turn pass with `BASEFANTASTIC` — is recorded in §5, not settled. F245 already ruled on
  which position the calculator models; this reading does not reopen that.
- The scan in §3.3 is of `CASTER.EXE` as shipped in
  `Raw install files/CoM2ModWarlord1.5.12.9/CoMWin1511/`; the compiled code is one executable for
  both builds, which is why §2 and §3.2 are stated once.
