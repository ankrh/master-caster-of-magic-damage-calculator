## Local binding and named route

The new loader splice compares the virtual reader's output with literal `True`, branches on the equality helper's returned flags, then writes 1 or 0 to `D[$708164] + i*$B8 + $50`. Each branch has its own checks and uses actual state if a check helper returns. The separate custom getter reads byte +0x76. The two bytes must not be conflated.

Both versioned INI records name [53] Vertigo, group 13, and [67] Mind Storm, group 14, with `Illusion=True`. Raw files do not establish which runtime loader branch ran or exclude later writes. Reuse the [existing loader](F250.2.loader.evidence.md) for reader/VMT, other key assignments and bounded startup/cache context; this unit adds only the missing Illusion-key writer and flag-returning string comparator.

| Completed animation → effect | Signed counter/speed quotient > length clears animation. A fresh combat check must pass; SpellBeingCast then reads the current spell, forwarded through $6456D8 to existing $5C9AAC. |

For the supplied group values, a nonzero custom result enters the custom route before the named animations. With zero custom result and later group reads reflecting those records, bits 53/67 are clear and their local ID branches are reached. Each check is a live call/read, not a cached immutable spell description.

Storing animation is not a synchronous renderer call. Completion obtains the spell then present through $708D38, not a saved initiating ID. Scheduling and intervening state changes remain external; there is no proof that the eventual effect argument always equals the initiating 53/67. This does not require reconstructing a whole lifecycle to establish the local links.
