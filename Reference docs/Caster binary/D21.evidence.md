# D21 — `@Units@ApplyLevelBonus` reconstruction evidence

## Scope and provenance

Target: CoM2 1.05.11 `Caster.exe`, TD32 routine `@Units@ApplyLevelBonus`, half-open extent
`$005981F8..$00598D86` (2,958 bytes, 773 instructions). Binary identity is owned by
[`README.md`](./README.md). `tools/annotate_caster_disasm.py --inbound` reports this exact
enclosing routine and no straddling outer branch.

The durable source-shaped body is in
[`Units.RecalculateUnits.pas`](./Units.RecalculateUnits.pas), `procedure ApplyLevelBonus`.
Independent Claude and Codex cold derivations were reciprocally reviewed and revised on
2026-08-10. All six review findings were accepted; no semantic disagreement survived. Review
corrected the loader binding for the normal To Defend slot, a table-pointer count, complete
CoM2/Warlord value rendering, two documentation statements, and one frame-local declaration.

## Reconstructed behavior

The routine reads `BaseUnits[i].ishero` at `$00598223..$0059822B`, selects one of two paths,
adds level-table values to the calculated `Units[i]` record, and calls `@Units@SetMaxMp` in the
shared tail at `$00598D7E`. All 21 state writes are checked signed 32-bit additions. There is no
stat multiplication, division, rounding, replacement, clamp, or base-record write in the extent.

The two paths write the same ten calculated channels: Attack, conventional Ranged, Thrown, Fire
Breath, Lightning Breath, HP, Defense, Resistance, Hit and To Defend. Their gates differ:

- Hero Attack, HP, Defense, Resistance, Hit and To Defend are unconditional. Hero Ranged requires
  positive **base** `rangedtype`; hero Thrown, Fire Breath and Lightning Breath each require the
  corresponding **calculated** channel to be positive.
- Normal Attack, Thrown, Fire Breath and Lightning Breath each require the corresponding
  **base** channel to be positive. Normal Ranged requires positive base `rangedtype`, then
  `Ismagicalranged` selects the Magic- or Missile-Ranged table. Defense, Resistance, HP, Hit and
  To Defend are unconditional.
- Hero and normal Breath each use one shared table for both Fire and Lightning Breath.
- The common `SetMaxMp` call owns MP. The assigned extent itself does not write MP.

### Gaze result

**Death Gaze, Stoning Gaze and Doom Gaze receive no level strength in CoM2 or Warlord.** Modern
`unitT` stores those channels at `+$38`, `+$3C` and `+$40`. The complete operand and write census
contains none of those offsets. Attack-channel writes stop at Lightning Breath `+$34`, resume at
Hit `+$4C` and To Defend `+$50`, then Defense `+$64`, Resistance `+$68` and HP `+$80`.
`Ismagicalranged` only selects a value written to conventional `ranged +$24`. Neither current
`Levelbonus.INI` contains a gaze key.

## Table loading and current values

Every inline table access reads calculated `level` as a signed byte, applies `dec; cmp $13;
jbe/BoundErr; inc`, then indexes a pointer-loaded `array[1..20] of Integer`. The loader
`@Init@LoadLevelBonusINI` `$00630738..$00630F9C` loops from 1 through configured
`AbsoluteMaxLevel`, calls `ReadInteger(section, key + IntToStr(level), 0)`, and applies the same
1..20 store bound. At the default maximum 9, absent normal keys 7–9 are therefore loaded as real
zeroes; levels 10–20 are unvisited.

The final normal To Defend pointer has an executable anomaly: `$00630D7B BA580F6300` selects key
`ToDefend`, `$00630D8B BA540E6300` selects section `Hero`, and `$00630DA7..$00630DAD` stores the
result through `$00708268`, which the normal arm reads at `$00598D3E`. `[Normal]ToDefend` is dead
configuration. Both shipped files contain only zeroes in both To Defend sections, so the anomaly
is numerically invisible with current data but a modded nonzero `[Hero]ToDefend` reaches both
paths.
