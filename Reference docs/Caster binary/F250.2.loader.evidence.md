# F250.2 — spell configuration field bindings

The missing local key-to-field link is established: the INI loader supplies `SpellTypeGroup`
to dword `+0x2C` and `EnchantmentID` to dword `+0x90` of the runtime spell table. This
reuses the existing table accessor, converter and cast writers; none was reconstructed again.
The startup branch can instead select cached data. The fields used in an actual run remain
conditional on selected files and the initialization/runtime boundaries below.

by joining the four fragments. Earlier directory/pointer initialization is also excluded.

## Field binding and existing cast sources

| INI key | UTF-16 literal | Passed default | Dword store |
|---|---|---:|---|
| SpellTypeGroup | 0x62DD04 | 0 | 0x62BD5C → `[M32[0x708164] + i*0xB8 + 0x2C]` |
| EnchantmentID | 0x62E038 | −1 | 0x62C4DE → `[M32[0x708164] + i*0xB8 + 0x90]` |

Each fragment formats the current slot number as its section argument, calls virtual
ReadInteger, then reloads the slot before the store. The passing slot check is unsigned
0..400; the multiply is signed/overflow-checked, followed by address scaling. Values are
stored as dwords without a value clamp. The raw VMT/reader code supports the stated method
mapping under its object/runtime contracts. Default selection on a missing key remains
conditional on the string reader/parser contract; it is not a literal in the INI record.

[F264.1](F264.1.evidence.md#spelltablet-layout) already identifies the same pointer and
stride, and [F250.2's converter](F250.2.combat.reconstruction.md) reads those same offsets.
The [versioned claim inventory](F250.2.combat.evidence.md#dispatch-and-scoped-keys) therefore
has a binary key-to-offset connection, rather than only matching numbers. The versioned
values remain in that inventory/F250.1. Warp's missing EnchantmentID passes default −1;
its existing ID-89 cast dispatch is separate from generic enchantment conversion.

## Initialization branch and second loader

At `0x63663D..0x63664B`, the caller tests the result of FileExists for relative `Spells.dat`.
Its file path supplies record size `0x12038` and the spell-table pointer to file-runtime
helpers. This size equals 401 × 184, consistent with the [shipped raw table](F250.2.remaining-reconciliation.md).
The normal file continuation bypasses the first INI loader. The no-file branch calls that
loader at `0x6366C1`; the shown exception-handler continuation calls it at `0x6366B5`.
All shown returning paths join at the second-loader call `0x6366C6`.

The full second loader reads book/default-pick/retort settings and AI research priorities,
counts records, and reads `aireroll.ini`. Its direct spell-table accesses are only reads of
`+0x44`, `+0x20` and `+0x34`. No supplied instruction stores through its spell-table
addressing sequence. This is not an assertion of non-aliasing or preservation by opaque
callees. The canonical source retains its auxiliary writes, loop/index differences and
the five-row count reset versus six-row allowed increment; these are not calculator changes.

Installation guidance is separate evidence: [Warlord MODDING.INI](../Script%20source/Warlord%201.5.12.9/MODDING.INI)
line 35 tells modders to delete Spells.dat after changing Spells.INI. The
[manual](../CoM2manual.html) lines 7729–7735 likewise describes cache deletion as forcing INI
reading. This agrees with the shown branch, but does not prove automatic cache deletion
during Load Mod or the selected working/data directories of a particular installation.

## Limits, review and next scope

The source explicitly preserves failed-check continuations and unknown helper state effects.
It does not prove a full first-loader traversal, the original array declarations, allocation
or OS import behavior, exception propagation outside the supplied frame, or final state
across opaque calls. Do not reclassify those limits as a missing converter or cast writer.
Full named admission and unsupplied cast continuations remain separate; the
[recalculation assessment](F250.2.recalculation-assessment.md) remains unchanged by this loader.

Both initial derivations, reciprocal reviews in their original sessions, and fresh revisions
with own-answer/review/raw inputs completed successfully. The merge accepts the agreed
field/default/index/caller results and GPT's more explicit conditional source notation.
It rejects broad initial claims about absent writes, guaranteed startup/exception behavior
and original declarations. The merge also places ReadInteger's try-frame before ReadString,
matching the supplied `0x46C2E2..0x46C2ED` setup. No new raw bytes were needed for that correction.
