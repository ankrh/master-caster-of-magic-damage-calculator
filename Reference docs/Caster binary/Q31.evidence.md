# Q31 — `@Units@IsChaosUnit`, `@Units@IsDeathUnit`, `@Units@ChaosChannel`

## Scope and outcome

Settles backlog question Q31: what predicate `@Units@IsChaosUnit` computes. All three routines are
reconstructed to complete semantic instruction coverage. The executable identity is owned by
[`README.md`](./README.md).

| Symbol | Virtual extent | File extent | Size |
|---|---|---|---|
| `@Units@IsChaosUnit` | `$00594FE4..$0059504C` | `$001943E4..$0019444C` | `$68` |
| `@Units@IsDeathUnit` | `$0059504C..$005950B4` | `$0019444C..$001944B4` | `$68` |
| `@Units@ChaosChannel` | `$005950B4..$0059511F` | `$001944B4..$0019451F` | `$6B` |

Half-open total `$13B` = 315 bytes. `$0059511F` is a `$90` alignment NOP before
`@Units@oneunitmanaupkeep` at `$00595120` and is correctly excluded. No extent has an inbound
branch from outside itself.

**Answer: `IsChaosUnit` is not a realm test.** It is a realm test *plus a recovery clause* for the
case where a later block in the recalculation ladder has overwritten the unit's `race` field.

## The routines

All three read the **calculated** `Units[u]` record. Blocks are `exact`.

```pascal
function ChaosChannel(u: Integer): Boolean;      { $005950B4 }
begin
  Result := Units[u].EnchantmentFlags[EncCCArmor]    { cmp $005950EE; jne $005950F5 -> $00595113 }
         or Units[u].EnchantmentFlags[EncCCFlight]   { cmp $005950FA; jne $00595101 -> $00595113 }
         or Units[u].EnchantmentFlags[EncCCBreath];  { cmp $00595106; jne $0059510D -> $00595113 }
end;

function IsChaosUnit(u: Integer): Boolean;       { $00594FE4 }
begin
  Result := (Units[u].race = RCChaos)                    { cmp $0059501E; je  $00595022 -> $00595040 }
         or (ChaosChannel(u)                             { call $00595027; je $0059502E -> $0059503C }
             and Units[u].EnchantmentFlags[EncUndead]);  { cmp $00595033; jne $0059503A -> $00595040 }
end;

function IsDeathUnit(u: Integer): Boolean;       { $0059504C }
begin
  Result := (Units[u].race = RCDeath)                    { cmp $00595086; je  $0059508A -> $005950A8 }
         or (ChaosChannel(u)                             { call $0059508F; je $00595096 -> $005950A4 }
             and Units[u].EnchantmentFlags[EncUndead]);  { cmp $0059509B; jne $005950A2 -> $005950A8 }
end;
```

The second arm is a **conjunction**: the `je` at `$0059502E` / `$00595096` leaves for the False arm
without reading `EncUndead`. `ChaosChannel` evaluates Armor, Flight, Breath in that order, despite
the ascending constants being Breath, Flight, Armor.

## Calculated record, not base record

All three build the pointer `[global_00709188] + u*$1E1*4 + $06426898`. Two independent proofs that
`$06426898` is `Units` and not `BaseUnits`:

- `@Castercore@GetUnitData` uses `$06426898` at `$006473A1`; its sibling
  `@Castercore@GetBaseUnitData` uses `$01AC1798` at `$006473ED`. Both copy `$1E1` dwords.
- The gap `$06426898 - $01AC1798 = $4965100 = 40000 * $784` is exactly one complete declared array,
  and `Typedec.pas:336` declares them in the order `BaseUnits, Units`.

## Why the recovery clause exists

`race` is a single scalar that `@Units@RecalculateUnits` overwrites repeatedly, in this order:

| # | Block | Gate | Race write |
|---|---|---|---|
| 1 | CC Breath | `EncCCBreath` `$00599F0C` | `RCChaos` at `$00599F71` |
| 2 | CC Flight | `EncCCFlight` `$0059F354` | `RCChaos` at `$0059F3B2` |
| 3 | CC Armor | `EncCCArmor` `$0059F4C7` | `RCChaos` at `$0059F5A5` |
| 4 | Blood Lust | `EncBloodLust` `$0059F600` | sets `EncUndead`, then `RCDeath` at `$0059F68A` |
| 5 | (Life arm) | — | `RCLife` at `$0059F7A1` |
| 6 | Animated | `EncAnimated` `$0059F7FC` | sets `EncUndead`, `RCDeath` at `$0059F85A` |
| 7 | Undead normalization | `EncUndead` `$0059FBF4` | `RCDeath` at `$0059FC26` |
| 8 | No Heal | `EncNoHeal` `$005A0444` | `RCNoHeal` at `$005A0472` |

Every Chaos Channels variant first writes `RCChaos`. If the unit is *also* undead, block 4, 6 or 7
overwrites that one field with `RCDeath`. The flags still carry both facts; `race` carries only the
last conversion. The conjunction `ChaosChannel(u) and EncUndead` selects precisely the units whose
`RCChaos` write was destroyed, using the very flag that gates the destroying block.

This is live code, not a dead corner: the first classifier call (`$005A1274`) is after the shared
Undead write at `$0059FC26`.

`race` is the unit's **effective realm**, not a cosmetic field: `@Spells@CombatSpellAvailable`
reads it at `$005C1F7C`, does `add eax,-$10` at `$005C1F83` and dispatches through a five-way jump
table at `$005C1F96`; `@Aispelltargeting@AISpellWardTarget` uses the same `race - $10` idiom at
`$0055B0EB`.

### `IsChaosUnit` — recovery, `inferred`

The tail is coherent and load-bearing. The "natural" symmetric reading
`race = RCChaos or ChaosChannel(u)` would be strictly redundant in its first case *and* would
wrongly reclassify units the ladder deliberately moved to `RCLife` (block 5) or `RCNoHeal`
(block 8). Against that natural reading the compiled predicate is narrower by exactly:

```text
{ u : ChaosChannel(u) and not EncUndead(u) and race(u) <> RCChaos }
```

— Chaos-Channelled non-undead units whose race was taken by block 5 or block 8. Both are narrow
corners. Intent cannot be recovered from the executable; the fit is exact on both conjuncts and
the alternative reading has no mechanism.

### `IsDeathUnit` — the clone, and `BUG-Q31`

The same lemma does *not* rescue the sibling. `EncUndead(u)` already implies block 7 wrote
`race := RCDeath`, so the tail is subsumed by its own first disjunct in every case except after
block 8's `RCNoHeal` overwrite at `$005A0472`. In that corner it recovers Death membership only
for units that also happen to be Chaos-Channelled.

```text
BUG-Q31   { u : CombatEnchantmentFlags[EncNoHeal] and EnchantmentFlags[EncUndead]
                and not ChaosChannel(u) }
          -> IsDeathUnit(u) = False, though block 7 had classified the unit Death.
```

The otherwise identical set with `ChaosChannel(u) = True` returns True through the tail. The defect
is a **missing `EncUndead`-alone disjunct** in the No-Heal corner, not a spurious `and` — and it is
in `IsDeathUnit`, not `IsChaosUnit`. Reproduce it as written.

Second consequence to reproduce: a Chaos-Channelled undead unit answers **True to both**
classifiers, so any caller treating them as mutually exclusive realm tests applies both.

### Corroboration from the Spell Ward chain

The chain at `$005A5D36..$005A607F` decides three realms by direct `race` compare and two by
helper — and the split tracks exactly which realms the ladder overwrites:

**Loose end (`unresolved`).** Life *is* written by block 5 yet still gets a direct compare. The
recovery reading explains four of the five arms and not this one.
