# Execution representation

`Calculator/steps.js` owns invocation descriptors and occurrence identity. `Calculator/stats.js`
registers the existing calculator passes; this does not establish a binary call schedule.

- Source identity remains `phase:id`, including citations and `projectionOf` scope lookup.
- Each invocation has a run-local ID, routine, position, optional parent/request IDs, copied
  arguments and declared entry reads. Live record bindings stay in the execution context and
  are not serialized into trace metadata. These declared reads are selected entry snapshots,
  not an exhaustive account of every field the implementation reads.
- An occurrence identifies one invocation/source/local ordinal and carries its execution index.
  Sparse writes and boundaries preserve it through field, slot, channel and chance projections.
  The complete main-pass ledger also keeps skipped and no-op occurrences, materializing lazily.
- Source-write steps are atomic: invocation re-entry on the active run is rejected, including
  through a fresh context. Orchestration invokes routines between writes; `parentId` can link
  these calls. Call-local context is restored on return or throw; published context state and
  record mutations survive. Actual writes retain source ordering and uniqueness inside their
  call. Projected steps preserve original occurrence order and each origin call's phase order.

The current flat descriptor covers the existing preparation observations and main step walk.
Existing chance projections retain the original write occurrence; their attack-specific transforms
belong to calculator projection calls. The existing figure calculation has its own descriptor.
In a complete projection ledger, `executionInvocation` and `executionIndex` name the executing
projection visit while `invocation` and `occurrence` retain the original source write.
`statInvocations` and `statExecutionTrace` are non-enumerable diagnostic properties. Main-pass
ledger coverage has not been expanded to claim a complete engine lifecycle.

Hovers retain source labels and show call labels when their projected entries include repeated
invocations of a routine, numbered within that hover. A single calculation and its projection
do not need call headers. The UI does not collapse repeated source writes.

F279.3c owns the outer requested-cast executor; F279.3b owns Holy Weapon migration.
The current flat calculation and its numerical rules remain in place. No additional Specials
call, cast replay, split binary record model or full-pass equivalence is activated here.
