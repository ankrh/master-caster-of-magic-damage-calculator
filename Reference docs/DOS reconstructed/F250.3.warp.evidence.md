# F250.3 — DOS Warp Creature writer and local recalculation

The final Warp section of [combat.c](combat.c) reconstructs the missing spell89 caller and
writer in all three DOS builds. [Raw evidence](F250.3.warp.raw.md) contains the identical
668-instruction Method B packet, with trailing whitespace normalized for tracking.
[Flow diagram](F250.3.warp.flow.svg) shows the version branches. No calculator number or
provenance status changes; the parent F250.3 remains open.

## Result

The far call at `0x82DA3`, operand `0428:002A`, resolves through VROOMM entry133/slot2 to
`0xAE020` in every build. The writer ORs the battle record's `Combat_Effects` word at `+0x22`.
Its three masks match the existing [unitcalc.c](unitcalc.c) consumers:

| Input cast-state bit | Raw mask | Consumer, 1.31 / 1.60 / CoM1 |
|---|---|---|
| Warped Attack | `0x0080` | `[90A23,90A66)` / same / `[90749,90776)` |
| Warped Defense | `0x0100` | `[90A66,90AAD)` / same / `[90776,90795)` |
| Warped Resistance | `0x0200` | `[90AAD,90ACE)` / same / `[90795,907AA)` |

These are cast-state inputs in the battle carrier, not permanent `_UNITS` writes. The field
names come from existing reconstruction, joined only after both independent revisions.
The selected outcome does not itself apply the arithmetic: the known consumers do that.

MoM1.31 loads SI from `[BP+6]`, calls the opaque resident helper with3, and maps returned
1/2/3 to Attack/Defense/Resistance. An already-set selected bit sets a negative retry marker.
Other negative results retry; other nonnegative results exit without a local store. There is
no local retry limit. An all-bits-set infinite-loop example additionally assumes unchanged
relevant memory/addressing and a helper restricted to1..3; neither is proved here.

CP1.60 and CoM1 instead use inherited SI, leaving the caller's pushed word unread. They
compute ES:BX once and explicitly save/restore it around a local near wrapper's opaque call.
Their common cascade is:

| Reached test, in order | Local store when true |
|---|---|
| First call(3) returns1 and Attack is clear | OR Attack |
| Second call(2) returns1 and Defense is clear | OR Defense |
| Resistance is clear | OR Resistance |
| Third call(2) returns1 and Defense is clear | OR Defense |
| Attack is already set | OR Defense, possibly already set |
| Otherwise | OR Attack |

This is a bounded local decision graph, conditional on calls returning, with one OR-store per
completed path. It is not1.31's retry loop. No random probabilities are claimed. CP's eight
prologue NOPs and107 exit NOPs execute; CoM1 returns at `0xAE0BA`, before its separately retained
post-return bytes. The source preserves actual stack operations and live state across calls,
without assuming even saved stack contents are protected from an opaque callee.

The resolved random target is `0x0FFA8`, also covered by the existing
[F6 range evidence](F6.evidence.md#result). Reuse its argument/return analysis before any
later probability question; the bounded return-range question is already covered. That
range evidence alone does not establish uniform independent draws or Warp-loop termination.

## Named routing and scope

Raw SPELLDAT record89 names Warp Creature and supplies class5, realm byte2 in every build.
The reused dispatcher `[81F4C,81F6F)` sign-extends class byte `+0x15`, checks its word value
unsigned against23, then selects the class5 table entry to `0x82B84`. This joins the raw record
to the named path under explicit runtime-loading/index assumptions; no loader is reconstructed.

Reused dispatcher comparison/branch: 131:`0x81F5D`,`0x81F63`; 160:=; com1:=.

The class5 prefix calls `0418:0043` for id89. All later tests use returned live DI: there is no
claim that this opaque call preserves it. The supplied sliced sibling heads lead to `0x82D59`
when their tests fail. The writer is invoked only if the call at `0x82D91` returns a signed
positive word. Its setup includes two pushed words, DX:AX pointing at a110-byte battle record,
CX=110, then calls `0000:0787` and `03D0:002A` with no intervening setup; cleanup is114 bytes.
The first callee's body is absent, so this packet does not promote a copy ABI or live-record
protection guarantee. Existing [combat.c](combat.c) `Combat_Resistance_Check` at `[98FCB,9900D)`
supplies the resistance-result interpretation for the second resolved target, without needing
another reconstruction of that callee.

The source-shaped fragment is machine notation, not a standalone C program or recovered
function signature. Its inline address macros preserve signed16-bit multiplication, low-word
offset wrap, and pointer reloads. The retained dispatcher repeats existing A32 context only.
Excluded sibling bodies, full admission/recast/clear/lifecycle and random/copy contracts are
outside this bounded unit; they are not grounds to rederive known consumers.

## Recalculation assessment

In1.31/1.60 the local tail runs after either outcome of the resistance gate, including when
the writer is skipped. It calls `03E0:003E` at `0x82DAA`, compares its result with battle byte7,
then calls **BU_Construct** at `0x82DFD` and **BU_Apply_Battlefield_Effects** at `0x82E16`.
Their raw destinations are `0x8EDFD` and `0x8FF09`; existing [R6.1b](R6.1b.evidence.md),
[R6.1c](R6.1c.evidence.md) and [R6.1d](R6.1d.evidence.md) own those bodies in unitcalc.c.
Afterward the tail reads the live saved equality flag: it either calls `03E0:003E` again and
writes returned AL to byte7, or writes the current saved byte there. Same-record restoration
requires the corresponding live addressing/frame state to remain stable across calls.

The known callee chain rebuilds derived stats and reaches the second Specials invocation before
the Warp consumers. This supports reusing that existing engine chain for these two versions;
it does **not** prove a full calculator pass equivalent. Such a pass must preserve the battle
cast bits, derived/base ownership, both Specials argument sets and ordering, intervening state
writes, and the entry/exit observations relevant to the calculator. Reattempting other selected
casts or copying permanent state over the battle carrier has not been justified.

CoM1 jumps from `0x82DA9` directly to the external `0x82E53` boundary. It performs none of the
local rebuild/byte7 tail. Its known Warp consumers still exist, but their existence cannot place
a recalculation on this cast path. Later scheduling and full-pass equivalence remain open under
the existing recalculation/lifecycle owners; no absence of recalculation elsewhere is claimed.

## Method B and validation

Both initial derivations received identical raw-only evidence in isolated directories. Both
reciprocal reviews resumed the original sessions; both revisions used fresh sessions with only
own derivation, the other's review and the raw packet. No expansion was needed.

|---|---|---|
| Initial / reciprocal review | `01a08fe1-1270-7e40-8798-710d422d6604` | `373778b7-2631-49a0-ba28-cca2e991a3ff` |
| Fresh revision | `01a08fe7-7c2a-7403-8254-5791152ee6a7` | `21a98dcc-21c9-4bfa-94bc-3e4b381d38c7` |

Original answers are immutable in `.derivations/F250.3.warp.*`; reciprocal reviews and logs
are under `.reviews/F250.3-warp*`. GPT corrected Claude's target arithmetic, opaque ABI,
live-state and termination overclaims. Both revised sources agree on masks, control flow and
local call order. The merge uses explicit machine-state operations; it excludes Claude's
remaining prototype comment that the callee “consumes” the cleanup bytes. Cleanup is performed
by the caller, and no formal consumption contract is established.

Raw validation checks all668 instruction rows against the three executables plus binary,
SPELLDAT and extent SHA256 hashes. Per-build citation coverage, source constants, diagram
rendering and repository citation checks are recorded in the scratch report. Citation checks
verify locations, not semantic correctness. Documentation/source transcription changes do not
require the calculator numeric/UI suites.
