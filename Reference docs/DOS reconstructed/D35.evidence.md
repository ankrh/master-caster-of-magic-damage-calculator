# D35 — CoM 6.08 Raise Dead reconstruction

Method 4 reconstruction of CoM 6.08 `WIZARDS.EXE` plus its runtime spell table. Calculator
verification scope: `com_6.08`. The source-shaped body and dispatcher fragment are in
[`combat.c`](./combat.c); this package changes evidence only, not calculator behavior.

## Interface and spell identity

The dispatcher pushes caller `[bp+0x0E]`, `[bp+0x0C]`, `[bp+0x0A]`, and derived local `[bp-6]`.
The callee therefore receives `(player_idx, caster_idx, cgx, cgy)` at `[bp+6]`, `[bp+8]`,
`[bp+0x0A]`, and `[bp+0x0C]`. The enclosing routine proves `[bp-6]` is the caster's controller
and `[bp+0x0A]` is its caster reference. Dispatcher `DI == 0x89` calls the routine; inequality
reaches the next spell comparison at `0x82EEA`.

`SPELLDAT.LBX` subheader `0x0220: D7 00 24 00` declares 215 records of `0x24` bytes beginning at
`0x0224`. Record `0x89` is `[0x1568,0x158C)`:

```text
52 61 69 73 65 20 44 65 61 64 00 00 00 00 00 00 00 00 00
4D 15 05 00 03 FE 00 28 00 00 05 FF 00 00 00 00 00
```

The first 19 bytes are NUL-padded `Raise Dead`, independently binding spell ID 137 from CoM-era
runtime data.

## Target selection and placement

The routine collects battle units whose signed status is greater than raw `3`, whose controller
matches `player_idx`, whose race is below `0x0F`, whose status is neither raw `6` nor raw `3`, and
whose persistent unit `wp` byte is not `9`. The second status-3 test is redundant after the
initial `status > 3` gate; value 3 remains conservatively named `BUS_UNKNOWN_3`.

Two eight-word locals hold near pointers to fixed 16-byte name buffers beginning at `DS:0x83E0`
and their corresponding battle-unit indexes. The executable has no eight-slot bounds check. The
28-byte CoM patch NOP run `[0xAB0DF,0xAB0FB)` lies exactly between the two local-array stores.

Nonzero players select candidate slot zero. Player zero also selects zero for a sole candidate;
otherwise the live builder pushes the candidate count, pointer array, zero, and prompt pointer
`DS:0x686F` before `0xAB19E`'s four-word call. `0xAB1A3: 83 C4 08` proves the arity. Dormant
`[0xAB18E,0xAB19E)` instead pushes fixed count 6, the same array, 1, and the prompt, then falls
into the call; live `0xAB18C: EB 10` skips it and no direct entry reaches it.

AI placement uses attacker-side x `14 - Random(3)` or defender-side x `8 + Random(2)`, y
`8 + Random(3)`, and repeats while the signed byte at the selected `DS:0xC524` row/cell is
nonnegative. It then consumes the externally selected battle-unit index at `DS:0x4995`, whose
producer store is `0xBB30D: 89 36 95 49`. Player zero instead resolves the local candidate index.

## Restoration writes

The selected unit's `Max_Figures` and `hits` are signed bytes. Even figures use bare byte
`SAR AL,1` and zero front damage. Odd figures use byte `INC AL; SAR AL,1`, and front damage uses a
separate bare byte `SAR AL,1` over hits. There is no signed-division correction idiom.

The success path then writes, in order:

- `Combat_Effects = 0` (`0xAB26F`);
- clear `Move_Flags & 0x1800`, the established conservative
  `MV_UNKNOWN_0800 | MV_UNKNOWN_1000` movement-recalculation flags, by byte AND `0xE7` at
  `BATTLE_UNIT +0x17` (`0xAB275`); this does **not** alter `_UNITS[].mutations`;
- clear the battle-unit enchantment dword (`0xAB27A`, `0xAB280`);
- copy current and target combat coordinates and clear movement/action, Web, confusion and
  outline state (`0xAB289..0xAB2D3`);
- write `race = rt_Fantastic_No_Realm` raw `0x15` (`0xAB2B8`), clear
  `USA_UNKNOWN_8000` by high-byte AND `0x7F` (`0xAB2BD`), and write the `Grey_Hits = -1`
  movement-cache sentinel (`0xAB2C2`);
- clear the persistent `_UNITS[unit_idx].enchantments` dword (`0xAB324`, `0xAB32A`). The same
  `_UNITS` base/stride and byte-identical stores are already bound to `u->enchantments = 0` at
  `combat.c`'s constructor source `0x97D0A/0x97D10`; they are not battle-unit attributes;
- recompute the persistent level, allocate/load a picture, set status Active, call `BU_Construct`,
  apply battlefield effects, and call the five-word external target `0xAF380` with
  `(battle_unit_idx,cgx,cgy,0x89,caster_idx)`.

Raise Dead therefore sets no enchantment flag. It clears both combat-unit and persistent-unit
enchantments and writes the unaligned Fantastic identity inline. This differs from the modern
No-Heal producer/recalculation handoff.
