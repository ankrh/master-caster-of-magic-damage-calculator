# F236.1 — Holy Weapon cast and global sources

Existing-source reconciliation, Method A. A Holy Arms grant predicate is not Holy Weapon cast
admission. Heavenly Light is a separate battlefield effect and does not cast Holy Weapon.
No calculator behavior is changed here; F236.2 and the Holy Weapon pilot own implementation.

## Heavenly Light's type test

CoM's existing battlefield block `0x905BB..0x9064B` requires the defender controller and the
battlefield city-enchantment entry. It starts `cl` from persistent mutations, then substitutes
Magic Weapons when persistent type is at least `0x97` (`0x905E7..0x905EE`). The later melee
and applicable ranged To Hit increments require zero weapon-quality bits in `cl`. Thus the
type ceiling withholds those increments through the same local weapon-quality test; it is
not a second independently granted enchantment or a universal rejection of the whole effect.
Positive melee/ranged strength increments, defense/resistance increments and the separate
Weapon_Plus1 floor remain in that block under their own guards.

This block is CoM-only in the three-build reconstruction. R6.1a's Q18 homolog analysis does
not locate the CoM in-attack `0x97` sites as corresponding MoM/CP `0x9A` attack gates. Do not
apply CoM's ceiling to the other versions on the strength of this source. This is scoped
coverage, not proof that no other routine anywhere tests unit type.

## Direct cast and custom-unit boundary

The direct-cast mark, owning-wizard Holy Arms, and battlefield Heavenly Light are different
inputs. The current calculator exposes Holy Weapon but no independent Holy Arms control.
Do not silently interpret every marked Holy Weapon as a Holy Arms grant or add a global control
as part of this evidence pass.

For modern casts, [F264.1](../Caster%20binary/F264.1.evidence.md) already maps the group-15
target predicate to base Fantastic, and the census records Holy Weapon's versioned group-15
metadata. That is partial target evidence, not a complete cast traversal. For DOS, these
grant/effect bodies establish no direct Holy Weapon target gate. The existing P1/P2 pilot
slices own the missing cast entry, complete admission, backing store and caller timing;
reconstruct only the specific absent portions, not the grants above.

F236's approved custom-unit policy uses the Fantastic input when no template ID exists.
That is a calculator discriminator, not an engine instruction: CoM actually reads persistent
type. Roster handling must keep the exact `< 0x97` comparison; a later conversion of battle
Fantastic does not change the source type. Custom fallback must be applied only to that
source-specific grant, never generalized into a direct-cast gate from this evidence.
