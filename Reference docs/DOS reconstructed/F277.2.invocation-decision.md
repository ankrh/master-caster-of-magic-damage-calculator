# F277.2 — Explicit Specials invocations

The user selected this design on 2026-09-10: reuse one Specials routine, give each invocation
its own position and arguments, and show each invocation in the execution/hover trace.
This document records the decision and its implementation handoff; it changes no calculator code.

The [execution census](F277.1.execution-census.md) supplies the existing source facts and
per-step classification. Use its two caller argument snapshots and intervening writes when
designing CP 1.60 and CoM 6.08 execution. A routine being invoked twice does not mean that
every effect writes twice. The completed [MoM 1.31 local-call ledger](P8.1.mom131-specials-calls.md)
supplies that version's arguments and reset/retain boundaries; its second mutation argument
is not CP/CoM's zero. Enclosing cast timing remains a separate claim.

F279.2 should separate the identity of a shared source step from the identity of an occurrence
of that step in a call. The existing `phase:id` chain/scope key does not by itself distinguish
two occurrences. Exact ID syntax, data structures and trace presentation remain design work;
the decision does not require duplicate implementations or new phase names.

Each invocation must use its own arguments and running record state. Changes between calls
must be visible only to the later call. Writes to the battle enchantment field do not change
the current call's copied `ench` argument. Local state within a call remains mutable: CoM Blood
Lust can change its local mutations byte, which subsequent logic in that same call must see.
Constructor-only, battlefield-only and external
handler writes remain at their own sites. The distinct HP rebuild helpers are not repeated
additive Specials steps.

F279.3a implements the invocation support needed by the pilot, F279.3b exercises the Holy
Weapon route, and F277.3 extends it across the remaining DOS schedule. F277.3 also retires the
temporary combat-summon conversions at the head of region `a`, placing them at their evidenced
caller boundary. Future implementation must report numerical changes and show both occurrences
in the trace when they execute. This decision alone does not settle the outstanding cast
admission and timing gaps identified by the completed P1/P2 inventories and the census.
