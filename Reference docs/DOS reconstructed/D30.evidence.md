Package and method: [`D30_D31_D32`](./D30_D31_D32.evidence.md), Method 4. Calculator scope:
`com_6.08`. This is evidence-only; calculator behavior is unchanged.

## Scope correction

The frozen row named CoM 6.08 `MAGIC.EXE`, 303,464 bytes, MD5
`b413b9df43eb0d2c0d5744be9e3410f8`. That module is not the repository-authoritative gameplay
implementation binary. The authoritative identity route in
[`MoM binary analysis.md`](../MoM%20binary%20analysis.md) assigns CoM 6.08 mechanics to the
companion `WIZARDS.EXE`, 1,006,232 bytes, MD5 `d92830af2c18fd57e82f26d6c690af82`.
The frozen module's complete `[0x000000,0x04A168)` frontier contains neither the exact helper nor
its shorter arithmetic signature; those negative scans corroborate the identity correction but
are not the basis for it.

## What the bytes do and do not prove

The first helper computes signed `sar16(roll - 5, 1)`. The second replaces post-defense damage
with that floor only while `defense_special < 80` and raw attack flag `$0020` is set.

The `$0020` binding is unresolved. Existing CoM 1 source evidence also uses `$0020` as
`ATT_DESTRUCTION`: item `IP_DESTRUCTION` projects it at `com1:0x8E550`, and the combat
Destruction save path consumes it. The bytes therefore permit two readings: Supernatural also
projects to that bit, or this is a Destruction floor and the Supernatural consumer is elsewhere.
This item closes as a scope correction plus a bounded **consumer candidate**, not as proof of the
Supernatural gate.

The `defense_special >= 80` exit is behaviorally material. CoM 1's full-block special-defense
sentinel is 100, so the floor is suppressed for a full block. Any later calculator implementation
must retain that condition if this candidate is proved to be Supernatural's consumer.

## Successor frontier

The corrected successor must use CoM 6.08 `WIZARDS.EXE` and prove the Supernatural
ability-to-attack-flag binding in either direction. Starting anchors are the ability projection
cluster at `0x8F5FF`, `0x8F616`, and `0x8F644`, plus attack-attribute accumulation at `0x99AA1`
and the melee/ranged OR sites already named in `combat.c`. If those falsify the candidate, the
successor must locate and bound the distinct Supernatural consumer. The owning source-shaped file
remains [combat.c](./combat.c).
