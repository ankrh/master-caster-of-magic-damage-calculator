# P1.1 — DOS cast-exit bridge

Method B reconstruction of **25 instructions / 61 bytes** across MoM 1.31, CP 1.60 and
CoM 6.08. Canonical body: [combat.c](combat.c), `external_82F61` and `p1_exit_82A9C` within
the existing analysis wrapper. No new game function or ABI is invented. [Raw packet](P1.1.raw.md)
records binary identities, exact bytes, counts and byte-backed VROOMM resolution. The
[flow diagram](P1.1.flow.svg) distinguishes this bridge from already reconstructed callees.
No calculator behavior or numerical provenance changes.

## Result and existing-source joins

All builds call `0318:0020` at `0x82F61`, then `0008:0503` at `0x82F66`. The verified targets
are `0x767A0` and resident `0x6DC3`; both remain opaque here. MoM/CP then execute the
five-instruction far-return epilogue. CoM instead jumps at `0x82F6B` to `0x82A9C`, pushes
the word at **then-live DS:C520**, calls `03D0:004D` at `0x82AA0`, pops CX and executes
the corresponding epilogue. There is no spell test in these 25 instructions.

Integration reuses the [P1 inventory](P1.holy-weapon-cast-boundary.md) and
[F250.3 class-1/15 writer](F250.3.mind-truesight.evidence.md). The already-covered incoming
jumps were checked directly in each binary: MoM/CP `0x82778` bytes `E9 E6 07` and CoM
`0x826C9` bytes `E9 95 08` each reach `0x82F61`. The class-15 table word `FD 22` at
`0x82F8F`, with existing CS base `0x80330`, selects `0x8262D`. All three independent
SPELLDAT record-124 reads at `0x1394` still supply Holy Weapon, class 15 and mask
`0x00800000`. These checks join existing source; they do not reconstruct another dispatcher,
writer or loader. Preserve P1's live spell/index/target and returning-call conditions.

The CoM third-call target resolves to the already reconstructed
[Calc_Battlefield_Bonuses](R6.5d.evidence.md), `0x9A8AB`. Under the documented DS binding,
the pushed word is the existing `_combat_structure` location; P1.1 alone does not prove
DS preservation across the two earlier calls. Its known CoM tail jumps at `0x9ACFE`
(`E9 73 EB`) to `0x99874`, already owned by [R6.2b](R6.2b.evidence.md). That existing
post-tested battle-slot loop invokes the constructor at `0x9988B` (`03A0:003E` → `0x8EDFD`),
then battlefield effects at `0x99892` (`03A0:0052` → `0x8FF09`). These bytes/targets and
the R6.5d extent hash were rechecked; the callee bodies are reused, not duplicated.

Thus CoM's bypass of the **local** class-1/15 constructor/battlefield tail does not imply
absence of later rebuilding: this continuation reaches its known broader aggregation and
slot-loop path, subject to its actual input and call conditions. MoM/CP already rebuild in
the preceding local tail; the newly supplied MoM/CP bridge establishes only the remaining
opaque calls and far return. It neither proves those opaque calls cannot recalculate nor
adds a known aggregation call to these old-build fragments.

## Machine-state limits

The C-shaped primitives use live machine state. `push16(v)` evaluates v, decrements SP by
two and writes through SS:SP; `pop16()` reads that stack word and advances SP by two.
`opaque_far_call` includes the architectural CS/return-IP pushes and the opaque transition.
`machine_retf16()` pops IP then CS and transfers without an immediate cleanup operand.
All stack offsets wrap to 16 bits. File offsets are not the runtime IP values pushed.

At epilogue entry, with SS=Q, SP=S and BP=B, DI reads Q:S, SI reads Q:(S+2), SP is set to B,
BP reads Q:B, and RETF reads IP/CS from Q:(B+2)/(B+4), leaving SP=B+6. No relation between
S and B is established. Calling this restoration requires an intact matching outer frame;
merely returning from an opaque call does not prove it. CoM's POP CX similarly reads the
then-current stack top; it consumes the original pushed word only under matching stack and
memory conditions. No semantic return value or full argument convention is established.

There are stack writes, but no explicit non-stack data-memory writes in this packet.
Other entries to the CoM island are outside this local scope. Complete target admission,
frame/entry provenance and transitive opaque-callee effects remain separate claims. The
known rebuild connection does not prove equivalence to a full current calculator pass after
every attempted effect; F279.2 must retain the actual scope, order, persistent writes and
reset/copy semantics.

## Method and validation

Both raw-only initials intentionally covered just the exit fragment. Holy Weapon's raw record
and already-covered dispatcher/writer context were checked separately for integration above;
they were not needed to derive the exit instructions and were not supplied as reconstructed
initial inputs. This separation prevents the 25-instruction result from claiming complete cast
identity or admission. No new source was derived from the integration checks.

Astra medium and Claude Fable 5.1 medium derived independently, reviewed each other in their
original sessions, then revised in fresh sessions with only their own initial, received review
and the raw packet. Both successful revised answers were read before merge. The merged body
keeps explicit machine effects and the common epilogue. Unsupported saved-frame relationships
and argument-cleanup inferences were omitted; no source disagreement remains in the merged
fragment. The immutable author artifacts are `.derivations/P1.1.{GPT,Claude}{,.revised}.md`.

Validation covers all binary/range hashes, exact instruction counts, raw overlay/resident
targets, incoming jumps, known-source joins, per-build ledger/annotation checks, local links
and rendered diagram inspection. This is reference source, not calculator executable code;
no numerical/runtime suite is warranted and no numerical gate is promoted.
