# F250.3 — DOS overland True Sight writer

[overland.c](overland.c) owns the local writer and supplied continuation in all three DOS
builds. [Raw evidence](F250.3.overland.raw.md) retains the 373-instruction packet;
[flow diagram](F250.3.overland.flow.svg) shows the build-specific sequence. This is a source
splice entered with `DI=131`, not a complete player cast or reconstructed loader.

## Carrier and binding

All builds OR live spell words `+0x20/+0x22` into the two-word carrier reached through
`DS:0x9EC2`, with unit index `[SS:BP-0x0A]` and stride `0x20`. Existing
[unitcalc.c](unitcalc.c) identifies this carrier as **_UNITS.enchantments**, low word `+0x18`,
high word `+0x1A`. The writer rereads its unit index and pointer before writing **high word
at `0xB3714`, then low word at `0xB3718`**. Both stores occur even if a mask word is zero.
Stack operations, address wrapping and live reloads are explicit in the source.

The three raw named record-131 images have low mask `0x0000`, high mask `0x0040`, and byte
`+0x17=3`. **If those bytes are present at the actual runtime reads**, the writer adds
True Sight's `0x00400000` input. This describes two 16-bit ORs/stores, not an atomic dword
operation. Earlier admission, DS/frame setup and data loading remain outside this unit.
This overland permanent-carrier write is distinct from the already reconstructed
[combat True Sight write](F250.3.mind-truesight.evidence.md) into battle enchantments.

CoM1 additionally tests the low byte of `[BP+6]` and the inherited unit pointer's type byte.
When nonzero caster byte and type-table bit `0x20` admit it, `0xB374A` clears byte `+0x0B`.
Existing unit/type layouts identify these as `_UNITS.Status` and `UA_CREATEOUTPOST` in
`unit_types[].Abilities` (`DS:0x019C + type*0x24 + 0x1E`). The source retains signed CBW/IMUL,
the inherited `ES:SI`, and the actual byte predicate. It does not substitute a refreshed pointer.

## Post-store sequence

The requested `DI=131` skips the retained Heroism comparison/call and the MoM Black Channels
mutation. At the common tail, MoM 1.31 and CP 1.60 are byte-identical. Their optional scan is
pretested and remembers qualifying noncaster indices. A signed-nonnegative result and live
spell byte `+0x17` equal to 2 or 4 admit the call at `0xB4880`. The address/byte is reread for
the second comparison. The raw True Sight value 3, if present at those reads, excludes it.
All ordinary MoM exits then clear three wizard words and perform the explicit far-return epilogue.

CoM1's `[BP-0x14]==1` route instead considers a loop when signed `[BP-0x32]>=301`.
Its first iteration precedes the count test; its eligibility byte is one byte earlier than
MoM's (`0xA353` versus `0xA354`, both signed-positive tests). Each admitted iteration calls
`0xA6BD1`, then `0x97B30`, then `0x979A2`, using actual returned live state. Six words are
pushed before the middle call, in instruction order. Existing `Create_Unit` reconstruction
in unitcalc.c owns `0x97B30`; it is reused, not newly reconstructed here.

After the actual `POP BX`, the added `0xB20C6..0xB20EB` fragment checks signed local value
370, a **nonzero** wizard byte, and live `DI!=0x22`. Its taken path sets `DI=0x1A`, performs
`XOR AX,AX`, clears `[BP-0x32]`, and jumps outside this splice to `0xB2C82`. Otherwise it
rejoins the three-word clear tail, calls `0x6DA79`, and returns. CoM1 recomputes the address
for the first two clears and reuses BX for the third; MoM recomputes all three.

No initial local value is supplied. Raw True Sight spell cost does not prove the live tail
local stays below either threshold. Returning opaque callees do not imply register, memory,
stack, flag or frame preservation, nor guaranteed loop termination.

## Recalculation assessment

The permanent enchantment store is established. The supplied sequence contains no direct
call to the known battle constructor or battlefield recalculation routine. That is a local
call-graph fact, not proof that no enclosing or transitive recalculation occurs. CoM1's
conditional Status clear and later calls/external branch must be preserved by any proposed
simplification. Full calculator-pass equivalence remains **unproved**: these extents alone
do not settle enclosing refresh ownership, persistent side effects or later eligibility.
No calculator number or provenance status changes in this source unit.

## Independent derivation and validation

Initial packet: 360 instructions. Both agents received the same 13-instruction CoM1 extension,
for 373 total (112 / 112 / 149). Claude's initial answer is preserved, but its expanded
continuation hit quota. The user-authorized replacement pair was **Astra medium + Sol high**.
Their original sessions performed reciprocal reviews; fresh sessions saw only each agent's own
initial answer, the other review, and raw evidence. Both successful revisions were read before
merge. Immutable outputs and logs live under `.derivations/F250.3.overland.*`; orchestration,
review and verification artifacts under `.reviews/F250.3-overland/`.

Astra's revised shape owns the merged source. Sol's reviewed corrections reinforce live flags,
reloads, actual stack operations and conditional runtime claims. Sol additionally supplied an
emulator parity helper that returns odd parity while claiming even parity (`0x6996` lookup);
that helper is not merged. Astra retains architectural primitive semantics instead of adding
an emulator implementation. The immutable answers preserve this discrepancy. No new binary extent was
needed beyond the shared extension. Hash/byte checks, citation coverage, local links, symbolic
constants, SVG XML and rendered diagram are checked for this documentation/source change.
