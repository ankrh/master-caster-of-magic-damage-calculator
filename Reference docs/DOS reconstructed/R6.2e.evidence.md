## Reading notes needed to check the bodies

1. **`push cs` + near `call` is a far call.** `Battle_Unit_Defense_Special` ends in `retf`
   (`0x9A79D: CB`) and takes its first argument at `[bp+6]`, so it is `__far`; the caller encodes
   it as `0x99EE5: 0E` (`push cs`) followed by `0x99EE6: E8 9E 06`. The R6.2c prototype at
   `combat.c:175` omits `__far`; this derivation writes it, and the discrepancy is flagged for the
   merge rather than edited into the shared file.
2. **The 32-bit enchantment pair is stored high-word-first in registers, low-word-first in
   memory.** `0x9A5EC: 89 46 FE` / `0x9A5EF: 89 56 FC` store `AX` to `[bp-2]` and `DX` to
   `[bp-4]`; every reload is `0x9A6C3: 8B 46 FE` / `0x9A6C6: 8B 56 FC`, i.e. `AX` = the word at
   `[bp-2]` and `DX` = the word at `[bp-4]`. The long therefore lives at `[bp-4]` with its low
   word at `[bp-4]` (`DX`) and its high word at `[bp-2]` (`AX`) — normal little-endian, but the
   register roles are the reverse of Borland's `DX:AX` return pairing. This is forced by the two
   `push ax / push dx … pop ax / pop dx` swaps at `0x9A5BA..0x9A5CF` and `0x9A5D3..0x9A5E3`, each
   of which exchanges the two halves. Getting this backwards inverts every mask below.
   Cross-check: the same layout appears in R6.2d's `Combat_Effective_Resistance`, where the Bless
   test at `0x99114` is `83 E2 00 / 25 00 02` — mask `0x02000000` — and `combat.c` already defines
   `UE_BLESS 0x02000000UL`.
3. **`test r/m16, imm16` followed by `jle` is `jz`.** `0x9A641: 26 F7 47 1C 02 00` then
   `0x9A647: 7E 09`. `TEST` clears `OF`, and `x & 2` is never negative, so `SF` is always 0 and
   `jle` reduces to `je`. Borland emits it because the source is `(x & 2) > 0`.
4. **`cwd / sub ax,dx / sar ax,1` is signed `/2`, truncating toward zero.**
   `0x9A770: 8B C6  99  2B C2  D1 F8`. Not an arithmetic shift: the `cwd`+`sub` biases negatives
   by one before the shift.
5. **`xor ax,8` clears, not toggles, at its site.** `0x9A622: 35 08 00` executes only on the
   `0x9A61D` fall-through, where the bit is known set.
6. **`tools/scan_mom_binary.py` misrendered `26 F6 47 16 98`.** At CoM `0x9EE33` this is
   `test byte ptr es:[bx+0x16], 0x98`; `mnemonic_16()` rewrote it to `cbw` because the
   instruction's *last byte* is `0x98`. Fixed in this session by gating the rewrite on Capstone's
   own `cwde`/`cdq` mnemonic. Any earlier dump of this address is wrong.

## E1 — `Battle_Unit_Defense_Special` `[0x9A587,0x9A79E)`

```c
/* Returns the defence value the attack resolves against. The result is not
 * `defense` plus bonuses in every case: DEF_SPECIAL_FULL replaces it outright.
 *
 * Frame: sub sp,6 -> [bp-2]/[bp-4] the combined enchantment long, [bp-6] the
 * override selector. Arguments are pushed by R6.2c at 0x99ED7..0x99EE4 in the
 * order si, [bp-0xe], [bp-0x18], [bp-0x14], [bp-0x10], so [bp+6] is the
 * defender index and [bp+0xe] the attack's magic realm.
 */
int16_t __far Battle_Unit_Defense_Special(int16_t defender_battle_unit_idx,
                                          int16_t attack_ranged_type,
                                          int16_t attack_immunities,
                                          int16_t attack_flags,
                                          int16_t attack_magic_realm)
{
    struct s_BATTLE_UNIT __far *bu = &_battle_units[defender_battle_unit_idx];
                                      /* di = [bp+6]; 131:0x9A58F  160:=  com1:= */
    int16_t defense_special = DEF_SPECIAL_NONE;
                                      /* C7 46 FA 00 00; 131:0x9A592  160:=  com1:= */

    /* Permanent unit enchantments, the battle unit's live enchantments, and the
     * battle unit's item enchantments, ORed into one 32-bit mask. Reading note 2
     * governs which half each OR lands in. */
    uint32_t enchantments =
          _UNITS[bu->unit_idx].enchantments  /* stride 0x20 via [0x9EC2];
                                              * lo 26 8B 57 18, hi 26 8B 47 1A
                                              * 131:0x9A597..0x9A5B9  160:=  com1:= */
        | bu->enchantments                   /* +0x3A lo, +0x3C hi
                                              * 131:0x9A5BA..0x9A5D2  160:=  com1:= */
        | bu->item_enchantments;             /* +0x2C lo, +0x2E hi
                                              * 131:0x9A5D3..0x9A5EB  160:=  com1:= */
                                      /* stored 131:0x9A5EC..0x9A5F1  160:=  com1:= */

    int16_t defense = (int8_t)bu->defense;
                                      /* 26 8A 47 05 / 98 / 8B F0 -> si
                                       * 131:0x9A5F2..0x9A605  160:=  com1:= */

#if BUILD == COM1
    /* 0x9A606..0x9A612 are thirteen NOPs. CoM 1 deletes the `mov ax,di /
     * mov dx,0x6E / imul dx / les bx,[0x922A] / add bx,ax` pointer reload here
     * and at 0x9A634, 0x9A652 and 0x9A670, keeping the ES:BX left by 0x9A5F9.
     * ES:BX is not written between those points, so every later field read is
     * still &_battle_units[di]. */
#endif

    /* Illusionary attack. The caller sets USA_IMMUNITY_ILLUSION in
     * attack_immunities when the attack carries ATT_ILLUSIONARY; the defender's
     * own Illusions Immunity clears it again, and anything still set here zeroes
     * the defence. */
    if (attack_immunities & bu->Attribs_1 & USA_IMMUNITY_ILLUSION) {
                                      /* 8B 46 0A / 26 23 47 18 / A9 08 00;
                                       * JE ->0x9A628, the second test
                                       * 131:0x9A613..0x9A61D  160:=  com1:= */
        attack_immunities ^= USA_IMMUNITY_ILLUSION;
                                      /* 35 08 00, store 89 46 0A
                                       * 131:0x9A61F..0x9A627  160:=  com1:= */
    }
    if (attack_immunities & USA_IMMUNITY_ILLUSION) {
                                      /* F7 46 0A 08 00; JE ->0x9A634, Large Shield
                                       * 131:0x9A628..0x9A62D  160:=  com1:= */
        return 0;                     /* 33 C0 then E9 64 01 ->0x9A798, the epilogue
                                       * 131:0x9A62F..0x9A633  160:=  com1:= */
    }

    /* Large Shield: non-melee attacks only. */
    if ((bu->Abilities & UA_LARGE_SHIELD) > 0
                                      /* 26 F7 47 1C 02 00; JLE(==JE) ->0x9A652
                                       * 131:0x9A634..0x9A647  160:=  com1:0x9A641 */
        && attack_ranged_type != RAT_NONE) {
                                      /* 83 7E 08 00; JE ->0x9A652
                                       * 131:0x9A649..0x9A64D  160:=  com1:= */
#if BUILD == COM1
        defense += COM1_LARGE_SHIELD_DEFENSE;  /* 83 C6 03; 131:—  160:—  com1:0x9A64F */
#else
        defense += MOM_LARGE_SHIELD_DEFENSE;   /* 83 C6 02; 131:0x9A64F  160:=  com1:— */
#endif
    }

#if BUILD == MOM131
    /* 1.31 tests the whole attack-immunity mask first and Weapon Immunity second,
     * so when both hold the later DEF_SPECIAL_WEAPON_IMMUNITY wins. The test is
     * word-wide, so USA_IMMUNITY_WEAPON in the mask also satisfies it. */
    if ((bu->Attribs_1 & attack_immunities) != 0
                                      /* 8B 46 0A / 26 85 47 18; JE ->0x9A673
                                       * 131:0x9A652..0x9A666  160:—  com1:— */
        && attack_ranged_type != RAT_NONE) {
                                      /* 83 7E 08 00; JE ->0x9A673
                                       * 131:0x9A668..0x9A66C  160:—  com1:— */
        defense_special = DEF_SPECIAL_FULL;
                                      /* C7 46 FA 02 00; 131:0x9A66E  160:—  com1:— */
    }
    if (attack_immunities & bu->Attribs_1 & USA_IMMUNITY_WEAPON) {
                                      /* 8B 46 0A / 26 23 47 18 / A9 00 01;
                                       * JE ->0x9A691 131:0x9A673..0x9A68A  160:—  com1:— */
        defense_special = DEF_SPECIAL_WEAPON_IMMUNITY;
                                      /* C7 46 FA 01 00; 131:0x9A68C  160:—  com1:— */
    }
#else
    /* CP 1.60 and CoM 1 swap the two blocks — Weapon Immunity first, the general
     * mask second — and narrow the general test to a byte, which puts
     * USA_IMMUNITY_WEAPON (0x0100) out of its reach. */
    if (attack_immunities & bu->Attribs_1 & USA_IMMUNITY_WEAPON) {
                                      /* 8B 46 0A / 26 23 47 18 / A9 00 01;
                                       * JE ->0x9A670 131:—  160:0x9A65F..0x9A669  com1:= */
        defense_special = DEF_SPECIAL_WEAPON_IMMUNITY;
                                      /* C7 46 FA 01 00; 131:—  160:0x9A66B  com1:= */
    }
    if (((uint8_t)bu->Attribs_1 & (uint8_t)attack_immunities) != 0
                                      /* 8B 46 0A / 26 84 47 18 — TEST *byte*, AL;
                                       * JE ->0x9A691 131:—  160:0x9A67D..0x9A684  com1:= */
        && attack_ranged_type != RAT_NONE) {
                                      /* 83 7E 08 00; JE ->0x9A691
                                       * 131:—  160:0x9A686..0x9A68A  com1:= */
        defense_special = DEF_SPECIAL_FULL;
                                      /* C7 46 FA 02 00; 131:—  160:0x9A68C  com1:= */
    }
#endif

    /* Magic Immunity, as a defence override rather than as an immunity bit. */
    if ((bu->Attribs_1 & USA_IMMUNITY_MAGIC)
                                      /* 26 F7 47 18 20 00; JE ->0x9A6B7, the Bless gate
                                       * 131:0x9A691..0x9A6A4  160:=  com1:0x9A691..0x9A697 */
        && attack_magic_realm > sbr_NONE
                                      /* 83 7E 0E FF; JLE ->0x9A6B7
                                       * 131:0x9A6A6..0x9A6AA  160:=  com1:0x9A699..0x9A69D */
        && attack_ranged_type != RAT_NONE
                                      /* 83 7E 08 00; JE ->0x9A6B7
                                       * 131:0x9A6AC..0x9A6B0  160:=  com1:0x9A69F..0x9A6A3 */
#if BUILD == COM1
        && attack_ranged_type != RAT_LIGHTNING_BREATH
                                      /* 83 7E 08 66; JE ->0x9A6B7
                                       * 131:—  160:—  com1:0x9A6A5..0x9A6A9 */
        && attack_ranged_type != RAT_FIRE_BREATH
                                      /* 83 7E 08 65; JE ->0x9A6B7
                                       * 131:—  160:—  com1:0x9A6AB..0x9A6AF */
#endif
        ) {
        defense_special = DEF_SPECIAL_FULL;
                                      /* C7 46 FA 02 00; 131:0x9A6B2  160:=  com1:=
                                       * (com1 pads 0x9A6B1 with one NOP) */
    }

    /* Bless. The realm gate is byte-identical in all three builds. */
    if (attack_magic_realm == sbr_Chaos || attack_magic_realm == sbr_Death) {
                                      /* 83 7E 0E 02 / JE ->0x9A6C3;
                                         83 7E 0E 04 / JNE ->0x9A72D, the elemental gate
                                       * 131:0x9A6B7..0x9A6C1  160:=  com1:= */
        if (enchantments & UE_BLESS) { /* mask 0x02000000: 83 E2 00 / 25 00 02;
                                        * JE ->0x9A6D6 (131/160) or ->0x9A6DC (com1)
                                        * 131:0x9A6C3..0x9A6D1  160:=  com1:= */
#if BUILD == COM1
            if (attack_ranged_type > COM1_BLESS_RANGED_TYPE_FLOOR) {
                                      /* 83 7E 08 27; JLE ->0x9A6DC
                                       * 131:—  160:—  com1:0x9A6D3..0x9A6D7 */
                defense += COM1_BLESS_DEFENSE;  /* 83 C6 05; com1:0x9A6D9 */
            }
#else
            defense += MOM_BLESS_DEFENSE;       /* 83 C6 03; 131:0x9A6D3  160:= */
#endif
        }

    /* Righteousness is INSIDE the Chaos/Death gate: 0x9A6C1's `75 6A` skips
     * 0x9A6C3..0x9A72C, which is Bless *and* the whole Righteousness block, and
     * lands on the elemental gate at 0x9A72D. The ledger's `Within 7` on the
     * 0x9A6D6..0x9A72D row says the same thing; an earlier draft of this file
     * closed the realm block after Bless, which contradicted its own ledger.
     * Corrected during reciprocal review on 2026-08-07; the independent
     * derivation and the ledger both had the nesting right. */

#if BUILD == MOM131
    /* Righteousness, read twice — once from the permanent unit record, once from
     * the battle unit's live enchantments. Both tests use the high-word bit
     * 0x4000, i.e. the long constant 0x40000000. */
    if ((_UNITS[bu->unit_idx].enchantments & UE_RIGHTEOUSNESS)
                                      /* pointer reload 0x9A6D6..0x9A6F0;
                                         26 8B 47 1A / 26 8B 57 18 / 83 E2 00 / 25 00 40;
                                         JNE ->0x9A722, the shared assignment
                                       * 131:0x9A6D6..0x9A701  160:—  com1:— */
        || (bu->enchantments & UE_RIGHTEOUSNESS)) {
                                      /* 26 8B 47 3C / 26 8B 57 3A / 83 E2 00 / 25 00 40;
                                         JE ->0x9A72D 131:0x9A703..0x9A720  160:—  com1:— */
        if (attack_ranged_type != RAT_NONE) {
                                      /* 83 7E 08 00; JE ->0x9A72D
                                       * 131:0x9A722..0x9A726  160:—  com1:— */
            defense_special = DEF_SPECIAL_FULL;
                                      /* C7 46 FA 02 00; 131:0x9A728  160:—  com1:— */
        }
    }
#elif BUILD == CP160
    /* CP 1.60 replaces the two record reloads with one test of the already
     * combined mask. It reuses 1.31's tail at 0x9A722 by an explicit jump. */
    if (enchantments & UE_RIGHTEOUSNESS) {
                                      /* 8B 46 FE / A9 00 40 — high word only;
                                         JE ->0x9A72D, elemental gate; else JMP ->0x9A722
                                       * 131:—  160:0x9A6D6..0x9A6DE  com1:— */
        if (attack_ranged_type != RAT_NONE) {
                                      /* 83 7E 08 00; JE ->0x9A72D
                                       * 131:—  160:0x9A722..0x9A726  com1:— */
            defense_special = DEF_SPECIAL_FULL;
                                      /* C7 46 FA 02 00; 131:—  160:0x9A728  com1:— */
        }
    }
    /* 0x9A6E0 is one NOP and 0x9A6E1..0x9A6E2 the tail of 1.31's `add bx,ax`.
     * The whole of 0x9A6E0..0x9A721 is unreachable in CP 1.60: an exhaustive
     * image scan for E8/E9/EB/Jcc edges into *every* address in that range
     * returns nothing. Retained verbatim under the ledger's `mom160` rows 9
     * and 10. Only 0x9A722 keeps predecessors — 0x9A6DE above, and the dead
     * 0x9A701 inside the orphan. */
#else /* COM1 */
    /* CoM 1 removes the Righteousness block entirely: 0x9A6DC..0x9A732 is
     * eighty-seven NOPs. 0x9A6C1's `JNE ->0x9A72D` and 0x9A6D1/0x9A6D7's
     * `->0x9A6DC` all land in the NOP field and fall through to 0x9A733. */
#endif
    }                                 /* closes the Chaos/Death realm gate opened
                                       * at 131:0x9A6B7  160:=  com1:= */

    /* Elemental Armor and Resist Elements.
     *
     * The two builds differ in *structure*, not only in constants and gate, so
     * they are written out separately rather than threaded through one shared
     * body: MoM/CP make the two bonuses mutually exclusive, CoM 1 makes them
     * independent. The whole difference is the two bytes at 0x9A753 — `EB 14`
     * jumping past the Resist Elements test in MoM/CP, `90 90` in CoM 1. An
     * earlier draft of this file rendered MoM/CP with an empty `else` and a
     * following independent `if`, which stacked both bonuses; corrected
     * 2026-08-07 on Codex's review entry 2. */
#if BUILD == COM1
    if (attack_ranged_type != RAT_THROWN
                                      /* 83 7E 08 64; JE ->0x9A769, Armor Piercing
                                       * 131:—  160:—  com1:0x9A733..0x9A737 */
        && attack_ranged_type >= RAT_MAGIC_FIRST) {
                                      /* 83 7E 08 1E; JL ->0x9A769
                                       * 131:—  160:—  com1:0x9A739..0x9A73D */
        if (enchantments & UE_ELEMENTAL_ARMOR) {
```

- `Battle_Unit_Defense_Special` is entered at `0x9A587`. A whole-image scan for `E8`/`E9`/`EB`/`Jcc`

- `Battle_Unit_In_City_Wall_Box` `0x9EFE3` is called from `0x9E63F`, `0x9E7E5` and `0x9EE08` in

- CoM 1's island `0x9EDD2` has exactly one predecessor in the image, the near `E8 60 04` at
  `0x9E96F`. Its loop back-edge `0x9EE1E ->0x9EDD4` enters the body below the counter

## Merged findings

1. Illusionary attacks reduce defense to zero unless the defender's Illusions Immunity clears
   the Illusionary immunity-mask bit first. Large Shield then adds +2 in MoM/CP or +3 in CoM to
   every non-melee attack type (`0x9A613..0x9A652`).
2. MoM 1.31 evaluates the word-wide general immunity intersection before Weapon Immunity, so the
   later Weapon selector can replace a full-immunity result. CP and CoM move Weapon Immunity
   first and narrow the general intersection to a byte, making the other applicable immunity
   dominant (`0x9A652..0x9A691`).
3. Magic Immunity supplies a full defense replacement for realm-bearing non-melee attacks. CoM
   excludes Fire and Lightning Breath, raises the replacement from 50 to 100, and changes Weapon
   Immunity from a floor of 10 to an additive +8 (`0x9A691..0x9A6B7`, `0x9A779..0x9A793`).
4. Bless and Righteousness are both inside the Chaos/Death realm gate. Bless is +3 in MoM/CP;
   CoM makes it +5 only for ranged types above 39. MoM's Righteousness reads permanent and live
   enchantments but not item enchantments; CP tests the combined mask and therefore includes
   items; CoM replaces the whole Righteousness region with NOPs (`0x9A6B7..0x9A733`).
5. MoM/CP grant Elemental Armor +10 **or else** Resist Elements +3 against non-melee Chaos/Nature
   attacks. CoM gates on `ranged_type >= 30 && ranged_type != 100`, raises the bonuses to +12/+4,
   and lets both stack. Armor Piercing halves the accumulated value afterward with signed
   division truncating toward zero (`0x9A72D..0x9A779`).
6. Wall of Fire triggers only when its battlefield counter is positive and a non-Flying,
   non-Teleporting, non-Merging unit moves from outside to a destination inside the inclusive
   `cgx 5..8`, `cgy 10..13` box. CoM additionally skips defender-controlled units and moves the
   current-square test after the destination test (`0x9EDB1..0x9EE60`, `0x9EFE3..0x9F046`).
7. The wall effect is Fireball-shaped and area-applied. MoM/CP pass strength override 0; CoM
   passes 10. The three-word local damage array has no initialization stores before the spell
   helper fills it (`0x9EE60..0x9EE7F`).
8. CoM's skipped near helper scans all 30 `s_NODE` records. A defender-owned Guardian node at the
   current overland action coordinates writes `owner_idx + 1` to battlefield Heavenly Light,
   raw offset `+0x1593` (`0x9EDD2..0x9EE20`).
